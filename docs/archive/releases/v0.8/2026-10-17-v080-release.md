# RawLab v0.8.0 Release Plan

> **For agentic workers:** Use the existing release procedure and focused verification. The coordinator owns version metadata, source freeze, integration and publication; independent workers own platform builds and read-only review.

**Goal:** Publish v0.8.0/build12 after the integrated source and release candidates pass, then produce a separate RawLab introduction video.

**Architecture:** Retain Gitflow: verified development -> release/0.8.0 -> main/tag -> development back-merge. Build all intended artifacts from one frozen candidate and publish corresponding source, dependency sources, checksums and provenance.

**Tech Stack:** Existing Swift/C++/Kotlin/WPF build scripts, GitHub Actions and GitHub Release.

**Spec:** [Release preparation and acceptance](preparation.md), [release procedure](../../../../agent.md).

- Keep the exact merged-development push CI gate, independently of the already green PR run.

- Ship macOS 14 arm64/x86_64 ad-hoc bundles, Windows x64 self-contained unsigned package and the existing-key-signed Android APK. iOS remains source/self-signing, with an optional explicitly unsigned build, not an installable/Store/TestFlight promise.

- Keep default release builds vendor-RUM-SDK-free. Do not add new features, credentials, original photos or private filesystem paths to public source.

Deliver horizontal and separately laid-out vertical versions. Use only the 20 owner-selected photographs in a separate clean application profile; never clear or load the normal photo-library profile.

## Review Focus

- Mixed version/build metadata or a new Android signing key must not break updates.
- Platform archives must include matching architecture/minimum OS, runtime libraries, resources and notices, without private RAWs or signing material.
- Formal publication authority must not be confused with third-party permission clearance or unperformed physical-device acceptance.
- Source/provenance/checksums must identify the actual frozen and tagged tree; do not reuse a package from a different build configuration.
- Demo settings, recent files, edits and imports must be isolated from the owner's daily application profile.
