# RawLab v0.6.0 Release Plan

**Goal:** Integrate the completed master-recipe work into development and publish `0.6.0`, build `10`, through Gitflow.

**Architecture:** Reuse the isolated worktree, merge the feature through a PR to development, then create `release/0.6.0`. Only release metadata, documentation, packaging and necessary release fixes belong on that branch. Build all clients from its source, merge through a PR to main, tag the identical tree and backmerge to development.

**Spec:** The user's release request and README/changelog follow-up, root `agent.md`, and the existing cross-platform verification reports.

## Constraints

- Preserve the original checkout, original RAWs, reference photographs and external signing material.
- Keep macOS 15+, iOS 18+, Windows x64 and Android SDK 26+ requirements.
- Retain Android signing continuity, ad-hoc Mac signing and unsigned iOS distribution; do not claim physical iOS/native Intel coverage.
- Rebuild app/native outputs from release source; pinned dependency and compiler caches may be reused.
- Keep licenses, corresponding patched LibRaw source, exact-tree provenance and checksums with the release.
- No overwritten tags, bypassed branch protections, private assets or invented CI success.

- [x] Build/test both Mac architectures, signed Android Release, unsigned iOS device/simulator and Windows self-contained output; record actual gates and limitations.

Final remote delivery follows the procedure below; completion is evidenced by
the PRs, tag and GitHub Release rather than a post-publication source edit.

1. Commit/push release; merge PR to main without bypasses and verify its tree equals the built tree.
2. Tag main v0.6.0; package exact-tag source, patched LibRaw and SHA256SUMS.
3. Upload the eight assets to a draft, verify remote digests, then publish.
4. Backmerge main to development through a PR, verify both branches and retain build evidence.

explicitly authorized resuming delivery after all platform checks passed.
