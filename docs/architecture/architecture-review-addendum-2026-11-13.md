# RawLab 架构复审补充（2026-11-13）

## 1. 优先处理的发现

### Android 批量导出恢复可能删除已经发布的成片

相册导出先把输出 URI 和 `outputReady=false` 写入任务日志，随后写完文件并把 MediaStore 的 `IS_PENDING` 设为 `0`。`BatchRunner` 在发布调用返回后才落盘 `outputReady=true`。进程如果在这两步之间退出，用户重开应用并点“查看任务”时，日志把 `PUBLISHING` 恢复成 `NEEDS_CONFIRMATION`，模型随即根据 `outputReady=false` 尝试删除该 URI。删除成功后，任务项回到 `PENDING`，可以再次导出。系统文件选择器的目录导出也有对应窗口，输出流已经关闭，日志仍可能只记录了 URI。 [相册发布](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/photo/PhotoStorage.kt#L432-L439) · [任务检查点](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/batch/BatchRunner.kt#L52-L64) · [目录写出](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/batch/publish/BatchOutputPublisher.kt#L110-L119) · [日志恢复](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/batch/journal/BatchJournal.kt#L80-L93) · [查看任务](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/MainActivity.kt#L257-L260) · [恢复删除](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/batch/BatchExportModel.kt#L360-L375) · [MediaStore 发布语义](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns#IS_PENDING)

Android 相机导入已经按 URI、内容和 `pending` 状态恢复，只清理能确认归属的未发布条目。批量导出可以沿用这条规则。MediaStore 用实际发布状态和内容核对输出，目录提供方用可验证的文件身份或摘要核对，无法确认的保留为“待确认”。回归应覆盖发布完成但日志尚未写入、已知半成品、读取权限丢失三种状态，分别断言保留成片、清理半成品和保留待确认状态。 [相机导入恢复](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/camera/CameraImportStore.kt#L207-L219) · [待发布条目清理](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/photo/MediaPhotoLibrary.kt#L80-L86) · [现有半成品回归](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/androidTest/java/com/rawlab/android/export/RenderedDngInstrumentedTest.kt#L222-L248)

### iOS 三段抽样可能把旧原件登记为本次导入成功

#267 用类型、名称、大小和拍摄时间筛选历史记录，然后比较相机与本机文件首、中、尾各 `64 KiB`。如果这些信息和采样字节相同，差异全部落在采样区之外，代码仍会跳过下载，复用旧文件，并把旧文件的摘要写入当前任务的 `sourceDigest`，标成 `.saved`。手动选片与增量导入都经过这条接收路径。台账 L4 已记录误判风险，这里补齐了从候选匹配到写入成功状态的调用链。 [手动导入入口](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/UI/Camera/IOSCameraController.swift#L241-L248) · [增量导入入口](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/UI/Camera/IOSCameraController.swift#L339-L346) · [抽样与跳过下载](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/Core/Camera/CameraWorkspaceBackend.swift#L377-L439) · [候选条件与成功状态](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/Core/Camera/CameraOriginalStore.swift#L394-L463) · [整改台账 L4](remediation-plan-2026-11-13.md#e2-本次核实发现两份文档都没覆盖的)

路线图 Q7 计划将抽样移植到 Android。建议把抽样用于筛选候选，复用为 `.saved` 前用完整源字节或可信的相机端内容凭据确认身份。沿用已确认的增量起点减少扫描。现有负例修改中段和尾段内的字节，应增加同元数据、三段相同、采样区外一字节变化的用例，断言转入全量核对。这个触发条件已由代码确认，实体相机上的发生频率待验证。 [相机传输契约](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/docs/design/camera-transfer/sony-wifi-design.md#L288-L305) · [现有抽样回归](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/tests/CameraSkipAndLimitTests.swift#L753-L805) · [路线图 Q7](remediation-roadmap-2026-11-13.md#5-产品决策登记2026-11-13-裁定)

## 2. 仍值得推进的架构改进

### 四端用同一份场景验证编辑语义

#270 新增 18 条带目标初始状态的场景，Mac 和 iOS 的传输测试已使用它们。Android 和 Windows 仍有具体分歧。

- Android 从普通照片复制“全部”到 RAW 时，源的占位值 `sensor` 会覆盖目标曝光基准。Windows 会把普通照片的默认镜头值合并进 RAW 目标，可能关闭已有校正。 [Android 曝光基准](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/adjustments/AdjustmentTransfer.kt#L130-L136) · [Windows 镜头合并](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabWindows/AdjustmentTransferValues.cs#L110-L121) · [占位规则](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/docs/design/editing-iteration/selective-payload.md#L115-L124)
- Android 把普通配方的曝光粘到 HDR 时直接写入逻辑值。例如曝光 `1.2 EV`、配方强度 `50%` 时，Apple 两端和 Windows 写入 `0.6 EV`，Android 写入 `1.2 EV`。 [Android HDR 粘贴](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/adjustments/AdjustmentTransfer.kt#L220-L243) · [Apple 强度换算](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/Shared/HDRAdjustmentTransfer.swift#L102-L117) · [Windows 强度换算](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabWindows/HDRAdjustmentTransfer.cs#L74-L93)

先让四端测试从实际 `prepare` 入口消费同一份场景，并补上普通配方到 HDR 的强度用例。编辑记录另外准备各端的历史原始样本，共用逻辑字段的期望值，覆盖缺省字段、休眠 HDR、未知版本和单条坏记录。各端继续用现有持久化适配器读取本端历史格式。 [共享场景](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/Shared/fixtures/adjustment-transfer-scenarios-v1.json) · [iOS 测试入口](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/tests/AdjustmentTransferTests.swift#L719) · [Mac 测试入口](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabMac/tests/AdjustmentTransferTests.swift#L869) · [编辑记录、传输与配方的边界](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/docs/design/editing-iteration/technical-design.md#L40-L54)

### 缩小存储读取和渲染会话的成本

- **iOS 最近照片。** 编辑提交触发最近照片重载，列表为每张照片调用一次 `readState`，每次都重读 `edits.json`。参考 Android 的 `readStates`，先为一批照片读一次记录快照。验收时直接统计整文件读取次数，并覆盖其中一条记录损坏的情况。 [iOS 提交后刷新](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/UI/Editor/ContentView.swift#L197-L200) · [逐张读取](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/Core/Persistence/IOSPhotoPreviews.swift#L147-L163) · [Android 批量查询](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/java/com/rawlab/android/settings/EditPersistence.kt#L85-L93)
- **iOS 普通图片预览。** `processBuffer` 建立临时会话。Lensfun 已打包时，每次会话初始化都会加载镜头库，包含 XML 解析和指纹计算。先在连续滑动预览中记录加载次数，再评估能否按镜头库内容身份复用已解析的库。 [临时会话](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/Core/RawProcessing/Sony2FujiProcessor.swift#L488-L495) · [镜头库加载](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLab/RawLab/Core/RawProcessing/Sony2FujiProcessor+Lens.swift#L145-L157) · [Lensfun 解析](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/lutools/src/core/lens_correction.cpp#L91-L119)
- **Android JNI 会话。** 全局 `sessionsMutex` 从句柄查找到原生渲染、像素复制和直方图统计一路持有，因此不同会话的处理也会互相等待。建议先固定句柄销毁、单会话串行、取消和 GPU 上下文归属的契约，再缩小全局锁的范围。两个会话同时发请求的回归应覆盖关闭与取消。并发数需按真机峰值内存决定。 [全局会话锁](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/cpp/rawlab_jni.cpp#L1455-L1474) · [像素复制与统计](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/RawLabAndroid/app/src/main/cpp/rawlab_jni.cpp#L1550-L1592) · [取消回调契约](https://github.com/dancancer/RawLab/blob/57dbea994e2ee683fdc86ccce887d33045c97989/lutools/include/sony2fuji/ffi/sony2fuji_c.h#L787-L799)
