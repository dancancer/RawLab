# 按 RAW 输入能力选择 AI 降噪路径

桌面 Mac/Windows 共用同一个 AI 入口，按输入能力选择下述路径。模型为可选实验资源，
不随普通构建提供；移动端尚未接入。处理不修改原始 RAW，现有编辑记录兼容。

## 目标与取舍

普通 Bayer 取消品牌、ISO、位深、压缩和分辨率白名单，优先沿用 DualDn。
非 Bayer，以及不能形成有效四相位 Bayer 输入的特殊解码结果，使用原生解码后的
通用 RGB AI。解码器不支持、损坏文件或真实资源不足仍明确失败。

跨品牌实验支持复用 DualDn 权重，但也证明不能把 Sony 同 ISO 噪声表当作通用标定。
因此采用“已有精确配置优先 + 单张 RAW 噪声估计”，不重新训练每个品牌，也不将
全部未标定 Bayer 一律切到 RGB。仅在 RAW 噪声估计不可信或官方 RGB 桥接不适用时，
使用同一个通用 RGB 路径；推理、文件或模型错误不能触发换模型。

## Bayer 噪声估计

现有 A7C II 标定及其采集条件保持不变。其他普通 Bayer 以各相位自己的黑位和白位
将原始 DN 归一化，统计之前不裁掉低于黑位的有效读出噪声，不使用 WB 后数据或 ISO
猜测噪声。两个绿色相位分别采样，反射 padding 不参与估计。

固定协议 `rawlab-bayer-noise-v3`：从覆盖全图的确定性 64×64 sensor 块中取同相位
Haar 高频差分，以 MAD 估计方差。粗尺度结构筛选之外，在 16×16 差分网格的横向、
纵向和两个对角方向检查间隔 1–4 的归一化相关性，拒绝绝对相关系数大于 0.3 的块，
避免单间隔恰好落在周期纹理的相关零点。保留的块
按相位均衡权重并做非负稳健拟合 `variance = k * signal + b`，`b` 是方差。
充分平坦但亮度跨度不足时允许标为 constant-variance 的当前图像估计，不声称能
辨识相机的光子噪声和读出噪声。没有可靠样本、严重相位分叉或结构污染时明确
返回低置信结果，选择 RGB 路径；不得默用 Sony 参数。

输出包含参数来源、样本数、拟合跨度和残差。来源标签区分 measured、estimated、
constant-variance；不是机型标定。噪声算法/配置版本和源文件身份进入 RAW 缓存键，
源数据相同才可复用确定性估计。算法、阈值或配置变化必须升级版本。
v3 的身份与 v2 不同，旧 RAW、依赖它的 RGB 以及通用 RGB 缓存均不会被复用。

## 路径选择与缓存

| 输入条件 | 路径 |
| --- | --- |
| 有效普通 Bayer，有匹配标定或可信当前图像噪声估计，WB/矩阵满足 bridge | 完整 DualDn RAW + RGB |
| 无可信 RAW 估计，或 Bayer bridge 无法表达当前 WB/矩阵 | 通用 RGB AI |
| X-Trans、线性/Stage3 DNG、其他可由原生解码返回有效 RGB 的 RAW | 通用 RGB AI |
| 解码失败、非有限数据、模型缺失/损坏、资源不足 | 对应错误，不伪装降噪成功 |

源文件身份、模型与解码/估计/适配协议、执行后端、白平衡和显影版本进入缓存身份。
RGB 路径的缓存还绑定镜头设置及实际加载镜头数据库的内容身份；它在镜头和方向之后。
DualDn 保留原有 RAW/RGB 两级缓存，WB 变化复用 RAW；RGB 修正使用独立缓存类型与
payload，不与 Bayer override 混用。准备结果选择确定路线；读取完整缓存确定实际路线。
不完整输出不得发布，失败的 DualDn 推理不得被 RGB 结果掩盖。

共享缓存和输入预算统一为 128,000,000 像素，不承诺所有设备都能处理该上限。

## 通用 RGB 模型

固定使用官方 [Restormer real denoising v1.0](https://github.com/swz30/Restormer/releases/tag/v1.0)。
[官方 demo](https://github.com/swz30/Restormer/blob/b19fa6e7104cb946ac8c5d6368117962ed0e751b/demo.py) 提供三通道 real-denoising
入口和分块参数，不需要相机 `k,b`。它在 SIDD/DND RGB 数据上训练或评估，不能据此
宣称已经验证各类 RAW 或线性 HDR 输入。

模型源码版本为 `b19fa6e7104cb946ac8c5d6368117962ed0e751b`，权重 SHA-256 为
`4cae18bed8a291b9a5deeeab48756bbe6f61fcf7f31a4cca0969b24608601387`。
导出器校验实际使用的架构、配置和权重内容；ONNX 与 Core ML 均为 float32。
输入为 `[1,3,640,640]` 的 `encoded_rgb`，输出为同形状的 `denoised_rgb`，网络已经包含
输入残差，宿主不得重复相加。采用 512 像素核心、64 像素 halo 和反射边缘，只保留核心；
这是 RawLab 的固定分块协议，不声称与上游 overlap-average demo 逐像素相同。

Mac/Windows 沿用 CPU、Core ML 和 DirectML 的现有后端策略。模型和数值验证入口见
[导出与使用说明](../../lutools/tools/dualdn/README.md)。导出成功不等于画质验收，后续
替换权重、输出域或分块规则必须升级协议并重新检查实际输出。

## 颜色与编辑契约

继续遵守 [颜色与渲染契约](../../lutools/docs/color-contract.md)。通用 RGB AI 使用现有
RAW 解码、黑位、用户当前白平衡、去马赛克和相机颜色矩阵。准备任务以全尺寸执行
原生 `RAWProcessor::process`，设置线性 sRGB 输出、关闭普通降噪、用户曝光为 0、
brightness 为 1，关闭基础曝光和嵌入预览曝光匹配。镜头校正和方向由现有原生流程
先完成；不另建未经验证的传感器坐标 RGB 解码器。

这份输出是模型适配器的权威输入：尺寸有效、三通道线性 sRGB、所有像素有限。
普通处理能将 3/4 个相机通道转换成上述结果的输入均可进入，包括已有支持的
Foveon/单色或特殊格式；不额外要求相机矩阵可逆。已有解码链拒绝的矩阵、RAW 或
只能降采样而不能全尺寸处理的输入保持拒绝。Stage3 已施加的内嵌几何不会撤销或
再执行一次；后续 Lensfun 能力仍遵守现有 Stage3/TCA 限制。

模型适配器不使用缩略图、嵌入 JPEG、用户曝光、LUT、曲线、用户裁剪或缩放后的
图像。RGB 模型需要编码后的有限范围 RGB，协议 v1 按以下方式定义：

1. 设原生 sensor 基准线性 sRGB 为 `L`，参考增益 `G = 2^sceneExposureEV(metadataEV)`，
   即现有 +0.7 EV 与文件 DNG BaselineExposure 的固定组合；不采用用户曝光或预览匹配。
2. 以现有中性显示曲线和 sRGB 编码构造 `P = neutralDisplay(G * L)`，模型读取 `[0,1]`
   的 float32 三通道 RGB。模型不接收线性 Adobe RGB；宿主渲染缓存中的 Adobe RGB
   与这里的模型输入明确分开。
3. 非有限模型输出导致整次任务失败。源线性最小值从 0 到 0.005 平滑增加修正，最大值
   从 0.85 到 1 平滑退出；输入/输出编码峰值从 0.94 到 0.99 继续退出。三者使用
   `smoothstep` 权重相乘，全部通道共用同一权重。权重非零时将负输出限定为 0，并计算
   `D = weight * (inverseNeutral(Q) - inverseNeutral(P)) / G`。负值、超白与病态区间严格零修正。
4. 缓存保存全尺寸、已执行镜头/方向变换的线性 sRGB 修正量 `D`，而非显示 RGB，
   也不是已经乘过宿主基础曝光的图像。identity 模型有严格零修正，因此无需依靠
   `inverseNeutral(neutralDisplay(L))` 的数值往返还原原始像素。
5. 渲染时现有 RAW 管线仍生成线性 Adobe RGB 图像；将 `D` 通过现有颜色转换矩阵
   转为线性 Adobe RGB，仅乘该次渲染实际使用的基础曝光增益后加到解码结果一次。
   用户曝光、外观、曲线和裁剪继续由后续原有阶段处理。

这个边界保留原始线性负值/超白值及已有曝光锚点，不把 SDR 模型输出当作新 RAW。
RGB 修正采用独立 payload/API，不塞进 `RAWBayerOverride`，也不套用其 camera-space
矩阵反变换。分块处理只建立当前块的编码输入和输出，避免同时保留多张全尺寸 RGB
中间图。

通用 RGB 缓存位于用户调色与裁剪之前，但在镜头校正和方向之后。曝光、外观、裁剪
和后续几何调整复用结果；**白平衡、原生处理版本或镜头校正参数改变时重算 RGB 路径**。
DualDn 的镜头处理位置和原有缓存规则不变。客户端请求身份和准备参数必须反映此差异，
不能给通用 RGB 路径复用旧镜头配置的结果。调整前参考图继续无 AI，统计来自实际帧。

上述保护区间和分块参数由 `rawlab-restormer-scene-v1` 标识；任何后续变化升级适配器
协议。验证需同时覆盖恒等、灰阶、高光、细节与实际样片，不能以“所有 RAW 可运行”
替代图像正确性。

## 缓存与模型包

将 AI 路线、模型摘要、解码协议、参考显示变换版本和噪声配置身份纳入缓存键。
通用 RGB 键还包含白平衡、处理版本和镜头配置；方向和 DNG 内嵌几何由源文件身份绑定。
DualDn 的 RAW/RGB 两阶段依赖关系继续保留；通用 RGB 缓存使用独立数据类型，不与
旧的 Bayer mosaic 或 camera correction 混读。
缓存同时校验 float32 payload 和元数据摘要；通用 RGB 必须先验证头部，才能信任其中
的旋转后画布尺寸，防止宽高损坏但像素数相同的缓存反复命中。

新模型包同时描述两条路线各自的资源和摘要。旧包缺少通用 RGB 模型时，对相应输入
报告模型资源缺失，不声称该相机无法降噪，也不静默使用普通降噪完成 AI 任务。
原始权重、导出模型、运行库、RAW 样片和缓存继续不入库；保留来源与原许可，
不将代码许可证自动当作所有权重的再许可。此设计不涉及发布或模型对外分发。

## 客户端与故障行为

两端维持一个“AI 降噪”开关，由共享核心自动选择路线。界面不要求用户选择模型或
手填噪声参数；诊断信息能够说明实际模型路线和执行后端。

沿用后台进度、分块取消、逐照片持久化、过期任务隔离、普通降噪参数保留和导出保护。
通用 RGB 任务可以没有 RAW 网络阶段，进度不能伪造该阶段已执行。只有完整有效结果
才将状态设为 ready。批量导出继续消费已准备结果；模型/源文件变化、损坏缓存和
白平衡变化必须按各自路线失效。

### 错误与重试

保留现有公共 C ABI 状态值，新增内部可辨认的错误原因与对应客户端文案：

- 缺少所选模型、摘要不符或图签名错误：配置/模型错误，保持失败；仅用户补齐资源后
  手动重试，不返回 `AI_NOT_READY`，避免自动准备循环。
- 完成缓存缺失、损坏或身份不符：`AI_NOT_READY`，按现有逻辑触发一次当前身份的准备。
  准备失败后进入 failed，不以重试循环掩盖原始失败。
- 源文件读取、解码不支持、内存不足分别保留现有 IO、unsupported、OOM 类别；
  解码成功但输出非有限属于处理失败，不发布部分结果。
- 后端失败遵守 Auto → 同模型 CPU 重跑；Force 明确失败。CPU 再失败则进入 failed。
- 取消沿用当前取消状态。首次开启尚未成功时不保存 enabled；已有 enabled=true 的
  记录在资源缺失、失败或取消时保持原值，阻止过期预览/导出，用户可关闭 AI 恢复普通处理。

运行路线从源能力和配置中确定；缺失模型、内存或临时 IO 不是触发换模型的条件。

## 验收范围

- 合成输入：identity、负值/超白、饱和颜色、暗部、不同 WB、奇偶尺寸、分块边缘，
  以及镜头/方向/裁剪组合；CPU 和硬件后端分别验证数值及失败语义。
- 真实输入：多个品牌 Bayer、A7C II 不同 ISO/RAW 模式、富士 X-Trans、普通线性 DNG
  与 JXL/Stage3 DNG；复用现有共享样片，补齐缺失类别，不把解码样片当作无噪声真值。
- 质量检查：同一显示变换下比较无 AI、普通降噪和 AI 的暗部、细纹理、边缘、颜色与
  高光；有合格配对数据时增加客观指标。单张视觉检查不等于所有机型质量认证。
- Mac 与 Windows 都覆盖实际模型执行、完整预览/导出、取消、重新打开、WB 失效、
  调整前后对比和 RGB 直方图；明确硬件、内存与未验证类别。
- 交付前验证当前 PR 的源提交、目标基线及 CI；合并授权继续遵守仓库流程。

完成条件是通用 AI 路径真实可用且通过上述契约验证，不是单独移除机型判断。
尚未实测的设备/格式必须在 PR 中列出；“可进入通用路径”与“已完成画质验收”分别记录。
