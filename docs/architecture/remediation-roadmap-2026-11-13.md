## 1. 目标

彻底消除累积的技术债，不搞临时方案、不做逐点缝补，为后续迭代铺路。可操作的判据不是「修完多少行」，而是 §3 的十条不变量成立。

## 2. 路线：先建编辑语义的规格层，其余双轨并行

**决定**：编辑语义层（参数规格、传输/重置规则、编辑记录格式、版本登记）**立即冻结单端修补**，所有跨端语义修复只能以「接入 conformance」的形式落地；语义层之外约 80 行按主题批次并行推进。

**依据**：

1. 共享向量机制**已经存在**（四端都在读 `Shared/fixtures/adjustment-transfer-v1.json` 等），缺的是**闭环**：不覆盖依赖目标状态的规则、不要求消费全部向量（Android 写死 `assertEquals(73, all.size)`）、没有字段全集可对账、平台差异被直接写进夹具当成真相。
2. 地基能直接关掉的行数只有约 10 行（<10%），价值在**掐断最贵的债源**：一个语义拆 4+1 个 PR 且多次误报——`#250` 没改 Android、`#267` 只改 iOS、Windows 重置漏半条。
3. 剩余约 80 行是单端或单层缺陷与性能问题，等地基只会白拖。

## 3. 十条验收不变量（技术债是否还清的判据）

只约束可观察行为，不约束实现。四套原生 UI、C++ 异常在 C 边界收敛、`Shared/` 只服务 Swift 双端、CLI 走 C++ 都不在约束内。

| # | 不变量 | 保证机制 | 违反时谁红 |
|---|---|---|---|
| 1 | 每个字段（含 HDR）的类型、范围、默认值、步长、精度、传输分组、重置分组、适用目标类型只在规格文件定义一次；四端与核心 CLI 逐项对账 | 规格表 + 每端 parity 测试 | 端模型测试；ctest；Contracts |
| 2 | 传输/重置/占位/版本比较规则用场景向量表达；每端按 id 集合消费全部向量，禁止写死计数；平台差异只能进 divergences 登记表，条数只减不增 | 向量 + consumer 测试 + 棘轮 | 端测试；Contracts |
| 3 | 每端每历史版本的记录都有 golden 样本，投影到字段 ID 空间后与共享期望一致；「未来版本」判定只读版本登记表 | 端样本 + 投影期望 + 版本表 | 端测试 |
| 4 | 同一批渲染请求在 GPU 后端与 CPU 参考之间差异在容差内；Auto 能回退，Force 不伪装成功 | 渲染对拍 | Mac 普通 PR 跑 ctest；Windows 硬件与 Android 真机作发布门禁 |
| 5 | C ABI 的结构布局、函数签名、枚举值全部进 fixture；`DllImport` 与 `external fun` 与之对账；JNI 包装面有契约测试 | fixture + 对账 | Contracts；本地 ctest |
| 6 | 并发与取消有一页成文契约，每条有测试锚点 | 契约页 + ctest | ctest |
| 7 | 每个测试源文件要么被构建系统发现并在门禁执行，要么列在 manual 清单并写明理由；**CI 出现 SKIP 一律算失败** | 对账脚本 | Contracts |
| 8 | 文件身份判定只有一条规则（stat 指纹优先、内容哈希兜底），三条热路径的整文件读/哈希次数有上限 | 存储契约 + 计数探针 | 端测试 |
| 9 | 产品版本号只有一处来源；核心源码只编译一次、依赖列表只有一份；仓库无本机路径与误跟踪产物 | Contracts；OBJECT library | Contracts；构建 |
| 10 | 跨端语义问题不能用单端 PR 关闭；每个「已修」都要有撤修复变红的锚点 | 台账纪律 + PR 模板 | 评审 |

## 4. 地基层形态（`Shared/specs/`）

- `adjustment-fields-v1.json`：每字段 `id / type / unit / min / max / identity / step / decimals / targets / raw_only / transfer_group / reset_group / reset_all / since / aliases / deprecated`。
- `versions-v1.json`：processing、hdr_processing、payload/scope、各端 record/journal/recipe 的 `min_readable` 与 `current`。
- `divergences-v1.json`：`{scenario_or_field, platforms, ledger_id, decision, owner}`；现有夹具里的 `platforms` / `platform_expect` 迁入这里。
- **暂不做代码生成**：手写规格 + 每端 parity 测试与生成防漂移效果等价，且不侵入四种类型系统与四条构建链。重新评估的触发条件：连续两轮新增字段因 parity 返工。
- `docs/design/editing-iteration/field-catalog.md` 删除数值，改为引用 JSON，避免两份真相。

| **P0** | 合入在飞 PR；定完决策；前置件：并发契约页（AR-4/C-N4/C-N5）、ABI fixture 扩签名与枚举（S4） | 4 | CI 快速通道；ctest | CI 不再空跑/flaky、fork 结果一致；决策清单关闭 |
| **P1** | 语义地基第 1–3 步：传输场景接入（含 Android A17/A18/白平衡/镜头、Windows 镜头、删写死计数、divergences 登记表）→ 字段表 + 四端 parity → 重置场景向量；旁路：C24、JNI 契约骨架、P/Invoke 对账、不变量 7 对账、渲染对拍 v0（Metal 对 CPU） | 6–7 | 端快速模型；Contracts；ctest | **四端在同一份场景向量上全绿，divergences 从 k 递减** |

| **P4** | 长尾：核心 CPU 性能批、端内性能与清理、Windows 目录分组、R10/R11/R13 | 多路 | 按批 | 只剩「延期决策」与「明确不修 + 理由」 |

- **最小可行路线**：P0 + P1 + P2 的 S1/版本表，约 2.5 轮。
- **理想路线**：P0–P4，约 4.5–5 轮。
- **止损点**：P1 结束若 Android/Windows 接入仍未绿 → 停止扩规格、只保留向量；代码生成永不主动启动；渲染对拍若 CI 跑不了 WARP/GLES → 只作发布门禁。

## 7. 双轨期间的插队准入（四条同时满足）

1. 不改变跨端用户可观察的编辑语义（涉及则必须在同一 PR 补规格行或向量）；
2. 严重度中到高、关乎 CI 可信度、可能丢数据或有安全问题、或已在飞；
3. 只动单端或单层，且带撤修复变红的锚点；
4. 不碰地基锁定的文件（`Shared/specs|fixtures`、四端 `*Transfer*` / `*Reset*` / `EditorAdjustmentRules*`、正在扩 fixture 的 ABI 头）。

## 8. 执行纪律

- **台账即真相**：只在代码核实后改状态；依据写成 `PR #NNN @ <commit>`；每条「已修」必须带验证锚点（命令 + 断言名 + 撤掉修复后应红的位置）。
- **复核方式**：独立复核直接按锚点复跑并撤掉修复确认变红；台账的「已修」不以 PR 标题为准。
- **divergences 棘轮**：每条平台差异必须挂一个决策或台账编号，条数只减不增。
- **平台归属**：`Shared/*.swift` 归 Apple；`Shared/fixtures`、`Shared/specs` 归规格 owner；`lutools/include/sony2fuji/ffi/*.h` 归核心。

## 9. 风险与反模式

1. **规格层变成第二份真相**：早期信号是 parity 出现 skip/白名单、divergences 不降反升、散文里又出现数值。对策：parity 进快速通道、棘轮 + owner + 到期轮次、规格设 CODEOWNERS。
2. **向量测到适配层而非真实行为**（L2 是先例：生产代码根本不走那条路径）：对策：conformance 必须调用生产入口、加「仅测试调用」检查、每个接入 PR 撤回一条规则证明变红。
3. **巨型重构拖垮迭代**：单 PR 除夹具超过约 800 行、schema 重写超过一次、整轮没关掉任何台账行。对策：规则用例子表达不做 DSL、每个 PR 必须关掉台账行或带来可演示绿灯。
4. **收益被高估**：AR-1 减少的行数、代码生成、「四路渲染对拍进普通 CI」（实际只有 Metal 对 CPU 能每 PR 跑）、Windows 目录分组（只改善 review 体验）。
5. **风险被低估**：S1 要准备四种原生格式的历史样本；第一版规格可能把 Mac 的 bug 当成真相；harness 手写清单会让每个 conformance PR 都在跟清单打架；存储批次改用 stat 指纹可能带来身份误判。
