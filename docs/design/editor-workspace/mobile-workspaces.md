# 移动端独立工具工作区

[统一可点击设计稿](mobile-review.html) · [现有四端设计板](index.html) · [相机工作区](../camera-transfer/prototype/workspaces.html)

这是 2026-11-10 已获用户实施授权的移动端方案 `mobile-r2`。iOS 与 Android 已接入原生独立工具工作区、局部草稿、紧凑参数和 JPEG 镜头 metadata 链路；评审与实施状态由 [manifest.js](manifest.js) 的 `proposals.mobileWorkspaces` 维护。桌面布局不在本方案范围内。可点击稿仍是设计资产，不能替代原生测试或相机硬件验收。

## 目标与依据

让用户先选编辑项，再进入适合该项的专用界面，始终能看清照片和本次调整的结果。编辑主页负责定位工具；进入工具后，主页分组导航退出画面。外观、曲线、HSL、色彩分级、几何与镜头使用各自的操作区域，不再塞进同一条通用底栏。

视觉沿用 RawLab 的中性深灰、系统字体、黄色功能强调和单一线性图标。普通动作采用统一的小圆角矩形或无底色图标按钮；快门、色轮、色相通道等有实际含义的圆形控件保留。照片以完整画幅显示，默认关闭额外照片边距，按原比例尽量撑满可用画布的宽度或高度；不额外缩小，不默认裁切。编辑控制不覆盖照片中心。

参考来源是用户通过 iPhone 镜像实际打开的泼辣编辑主页、调整、色彩、HSL、重构与滤镜页。借鉴的是任务入口、专用控制区和取消／确认的关系。社区、商业入口、教程、付费状态及其他产品功能不在参考范围内；没有修改或导出参考照片。

## 导航与状态

统一原型顶部可直接选择「编辑／相机入口／从相机导入／联机拍摄」。编辑主页顶栏的相机按钮进入相机入口；导入或最近照片的「打开编辑」回到编辑主页，相机入口返回也回到编辑主页。顶部切换是审核跳转，不替代应用内的连接流程。

| 所在位置 | 页面职责 | 返回与确认 |
| --- | --- | --- |
| 编辑主页 | 显示照片、六组工具入口、已改动标记；相册与导出留在顶栏 | 返回相册前沿用现有照片保存与任务守卫 |
| 工具工作区 | 显示本工具相关控制；底栏合并名称、取消与应用；复位与更多贴着画面边缘 | 底部固定「取消／应用」；应用后返回原分组与位置 |
| 精细数值 | 点击数值打开；展示完整数值、单位、范围和步进 | 取消只关闭数值输入；应用只更新工具草稿，不提前应用整项工具 |
| 预设、镜头配置等子页 | 只处理当前工具的选择 | 返回当前工具，不跳回编辑主页 |
| 导出、切图、离开编辑 | 不能带走未确认草稿 | 先处理草稿，成功后继续原动作；失败保留当前工作区 |

**所有移动编辑工具采用局部草稿。**进入工具时快照当前已应用值；同一工具的参数共享一个草稿；取消恢复进入时的该工具值；应用只提交本工具拥有的字段。应用成功作为一条可撤销操作，未变化的应用不新增历史。

工作区内的撤销／重做只影响当前工具草稿；主页的撤销／重做处理已应用历史。取消草稿不清空主页历史。复位只作用于当前工具的草稿，恢复契约默认值，而不是把所有字段设为零；整张照片复位仍在主页更多菜单中并明确范围。

Android 系统返回与 iOS 返回手势：有子页先关闭子页；工具未改动直接返回主页；工具已改动时提供「继续调整／放弃本次／应用并返回」。明确点击「取消」直接丢弃本工具草稿。应用期间阻止重复提交，失败保留草稿并提供重试。进入后台保存可恢复的草稿身份与内容，不自动应用，也不把旧照片草稿用到新照片。

原型中的页面选择器是评审跳转控件，不是产品导航；它可以直接查看各页，不代表真实的草稿离开流程。模拟图像只演示布局和轻量视觉反馈，不执行 RawLab 图像算法。

## 工具组织

保留现有六组和参数语义；独立 RGB 通道曲线和镜头配置暗角校正属于本方案的完整能力，其余算法范围沿用现有契约。主页组内工具可滚动，工作区内只保留本项相关控制。

| 组 | 工具与专用界面 |
| --- | --- |
| 外观 | 胶片外观和大师配方各有浏览界面；强度属于当前外观，并可精细输入；保留不同来源与身份 |
| 光线 | 曝光、高光、阴影、黑点、白点、对比度共享标量工作区结构；曝光保留当前 RAW 曝光基准与自动曝光；曲线使用专用曲线画布 |
| 颜色 | 白平衡显示色温和色调；饱和度与自然饱和度使用标量页；HSL 使用八色域与三轴；色彩分级使用阴影／中间调／高光色轮 |
| 效果 | 清晰度、去雾、暗角、颗粒；暗角高级控制由当前工具展开，不常驻主页 |
| 细节 | 锐化与降噪；降噪保留开关、保留细节／更干净预设及明度、色彩、粗粒噪点三个参数 |
| 几何 | 裁切、旋转和透视组成专用几何工作区；镜头校正使用元数据、匹配、配置选择与校正开关 |

普通标量可以共用组件，但进入每一项后必须有明确的任务名称、局部草稿和退出动作。这与当前在统一 dock 内切换数值的交互不同。复杂工具不能为了共用组件退化成普通滑杆页。

## 关键页面

### 编辑主页

照片占主要区域。主页顶栏只保留相册返回、照片身份、导出和更多；工具页取消独立顶栏。下方为六组入口及当前组四列紧凑工具；通常两行容纳当前组，超出部分滚动。没有参数行，也没有额外的复位／精细／更多工具行。已修改的工具使用标记与可访问状态描述。照片查看保留缩放、临时查看调整前及现有对比方式；不能用本次简化稿删除已有对比能力。

### 外观

一行容纳分类、搜索图标和导入入口；搜索默认收起。点击搜索后才显示输入框，关闭或清空回收空间。搜索不改变已选外观或强度；无结果时保留清空入口。分类、缩略图与强度留在当前工作区，取消恢复进入时的外观与参数。大师配方有自己的封面、说明和来源，不冒充同名胶片外观。

### 标量与精细控制

多参数页采用「名称／滑杆／数值」同一行，普通触点行高 48 dp；HSL 三行不再把名称和轨道拆成两层。曝光等单参数页保留完整宽度的标尺和一行数值。点击数值进入原生精细输入：Android 使用 Material 数值输入，iPhone 使用现有值轮；不再常驻「精细」动作行。现有降低拖动灵敏度的「精细拖动」仍保留在本工具更多菜单，它与精确数值输入是两种操作，不能相互冒充。开启状态通过菜单勾选与可访问说明表达。

### HSL、曲线与色彩分级

`mobile-r2` 按用户对首稿空间浪费的反馈收紧：删除工具页独立顶栏和底部解释文字，色域为一行 48 dp 触点，三轴各占一行，取消／名称／应用共用 48 dp 底栏。当前通道放在可访问名称和选中标记中，不额外占一条说明行。撤销、重做、复位、对比与更多贴预览边缘，不另占控制栏。

HSL 用选中标记区分当前色域，显示八个通道及色相／饱和度／明度；通道触点保持 44 pt / 48 dp，窄屏横滑，不能缩小触点硬塞一行。切通道保留各自草稿。曲线保留真实控制点编辑、通道、删除点与数值入口，色彩分级保留现有分区色轮。原型的曲线和色轮是布局示意；拖动、精度与算法仍需原生验证。

### 几何

裁切在照片上操作，角度标尺、画幅比例、翻转和旋转位于紧凑控制区。透视切换当前参数区，不重新显示主页工具。快照包含裁切、旋转、透视及相关联字段；取消必须整体恢复本次几何草稿。照片查看手势与裁切手势分开，不因点击裁切框而隐藏控制。

### 镜头与 JPEG

JPEG 镜头校正已接入移动原生客户端与共享 display-input 渲染路径。默认关闭，匹配、手动补值与可用能力必须来自实际 metadata 和配置；支持畸变、色差、配置暗角校正和自动裁边；暗角需要有效光圈及对应的 Lensfun 标定，缺少时说明原因并禁用开关。

| 状态 | 呈现与动作 |
| --- | --- |
| 元数据完整并匹配配置 | 显示相机、镜头、焦距、光圈；可更换配置；按支持能力开放畸变、色差和镜头暗角校正 |
| 信息缺失 | 显示缺失项并提供手动选择；必要信息未补齐前禁用相应校正，而不是笼统地写 JPEG 不支持 |
| 未匹配到配置 | 保留读取到的信息，提供搜索／手动选择；没有配置时不假装校正生效 |
| 已选择但配置不支持某项 | 单独禁用该项并说明原因，不让整页不可用 |
| 加载或校正失败 | 显示失败原因；保留选择与草稿；可重试或取消，不保存虚假的成功结果 |

JPEG 可能已有机内镜头处理，默认不自动打开校正。不能从文件扩展名或 EXIF 存在就断言是否已经校正。手动选择也必须具备渲染需要的有效相机裁切系数与焦距等信息；缺失字段要明确补齐。

实施时，JPEG 的结构化 EXIF 和手动选择必须传入共享镜头阶段，预览与导出使用相同语义，并处理方向、裁切与 metadata 所属照片。不得只移除 Android 门禁；不得让 JPEG 设置在 `effectiveFor(RASTER)` 中被静默清空后仍显示为启用。共享 C ABI、渲染顺序与跨客户端兼容须按 [颜色与渲染契约](../../../lutools/docs/color-contract.md) 验证。

### 降噪

用图像噪点／纹理语义的图标替换听觉图标，并与增加颗粒的图标区分。Android 保留现有普通降噪；不展示 Android AI GPU 降噪承诺。100% 查看用于检查细节，实际缩放必须读取原生预览尺寸，不能仅改一个百分比标签。HDR 降噪沿用自己的较窄控制集。

## 适配与能力边界

- 普通手机竖屏使用照片与下方工具区；横屏宽窗口使用照片左、工具右。工具区内部滚动，取消／应用固定在工具区边缘；不会把快门或应用按钮推出可见区域。
- 大字与短屏保留照片检查能力，控制按内容重排。照片最小空间是布局约束，不是通过缩小字体或触点兑现；必要时提供参数区折叠与全屏查看。
- 原型含普通竖屏、大字和短屏审阅入口；横屏与平板暂为结构规范，尚未画出完整可操作稿，不能标为已验收。
- Native 基础控件、系统返回、安全区、语义字号分别遵循 Android 与 iOS；本稿的浏览器控制只是设计表达。
- JPEG 白平衡、HDR、X3F NORMAL 等既有能力门禁不因这轮重新排版而自动放开。JPEG 镜头校正是本轮明确新增范围；其他格式扩展另有依据才实施。

## 与既有设计的关系

本方案已批准替代移动端的旧导航和操作摆放；其他平台保留原规范。具体冲突应明确处理：

| 既有规则 | 本提案 |
| --- | --- |
| 主页分组常驻，工具在统一调整区内切换 | 主页选工具，进入后隐藏主页导航，使用独立工具工作区 |
| 移动端单独的 Fine／Reset 操作组 | 工具标题与取消／应用合并到底栏；复位与更多在预览边缘；精细数值点数值进入，精细拖动在更多菜单 |
| 只有部分工具具有取消／确认 | 全部工具有本项局部草稿，确认后回主页；需扩展状态管理 |
| RAW-only 镜头入口 | 增加经过共享渲染接入的 JPEG 镜头校正；按缺失信息和配置能力给出状态 |

历史决策保留在现有 README 与 Git 中。`DESIGN.md` 已链接本方案作为移动端实施依据；原生状态与未验证范围单独记录，原型不表示所有设备能力均已验收。

## 资产与验证

- `mobile-workspaces.html` / `.css` / `.js` 为可维护源码，沿用本目录，不新建另一套设计站点。`scripts/export-mobile-workspaces.py` 从这些源文件导出对话内预览，避免维护第二套稿件。
- 图标为 Lucide 1.8.0 的有限子集，仅用于设计稿，许可位于 `shared/mobile-review-icons.LICENSE`；正式客户端沿用平台原生图标。
- 示例照片复用 [相机原型素材](../camera-transfer/prototype/assets/sources.json)，不是用户照片或算法输出。相机、镜头、数值和文件名均为示例。
- 横幅照片的完整画幅仍受屏幕宽度约束。回收的高度属于可用预览画布，竖幅与放大细节时可以使用；不能通过默认裁切横幅照片伪造空间改善。原型可点「适合」切换放大示意。
- 原型验证关注页面可达、搜索展开／收起、参数草稿示意、选择状态和窄屏布局；不等同于原生测试、算法验证或相机实测。
- 实施验收需要覆盖局部草稿、数值取消、工具复位、全局历史、后台恢复、切图／导出守卫，以及 JPEG 镜头 preview/export 一致性。UI 修改仍须在目标客户端实际运行验证。
