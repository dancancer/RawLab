# RawLab 四端应用设计资产

[打开四端设计稿](index.html) · [界面与状态覆盖表](coverage.html) · [元信息](manifest.js) · [产品路线图](../../architecture/roadmap.md)

本目录是持续维护的 HTML 设计原型，独立于应用代码。设计版本、评审状态、确认依据和实现状态只在 `manifest.js` 维护，设计板从该文件读取；设计版本不等于 RawLab 发布版本。当前原型只演示交互状态，不处理照片、保存应用数据、访问更新服务或执行安装。

## 范围与评审入口

| 平台 | 独立入口 | 布局与精确调整 |
| --- | --- | --- |
| iOS / iPadOS | [iOS](ios/index.html) | 手机底部面板；横向宽窗口旁置；44 pt 点击目标、现有刻度尺和单列完整数值选择；取消不改原值 |
| Android | [Android](android/index.html) | 手机底部面板；平板旁置；48 dp 点击目标、Material 数值对话框与系统返回语义 |
| macOS | [macOS](macos/index.html) | 左文件树、照片和底部调整区；950×620 最小窗口；数值框支持 Enter 提交、Escape 取消 |
| Windows | [Windows](windows/index.html) | WPF 窗口与左文件区、底部调整；1024×720 紧凑稿；数值输入及键盘焦点 |

资产覆盖四端当前已有的全部功能界面，加上本轮调整分组、HSL、前后对比及桌面自动更新提案。功能来源与平台差异通过覆盖表追溯：导入与权限、照片/目录浏览、现有调整工具、外观管理、对比和查看选项、单张导出、批量选片/确认/效果检查/任务/恢复，以及语言、触觉、渲染加速、隐私、关于和许可。系统照片/文件选择器、文件管理器与浏览器不另造一套界面，只设计进入、取消及返回结果的集成点。

第一步的编辑导航仅重新组织现有工具：外观、光线、颜色、效果、细节、几何与镜头。六个分组常驻可见，不用“进入 / 返回”切换：手机竖屏在底部单行横滑，横屏手机与平板在侧栏顶部一次全部显示，桌面在调整区顶部作为页签。点分组展开组内工具，再点当前分组收起面板，把空间还给照片。已调整的分组和工具用小点标出，完整说明放在可访问名称中。白平衡归颜色，强度归外观。混色器提供八色域、三轴、精确值和重置；八个色块始终一行，选中色只增加外圈，已调整的色域下方有小点；三条轨道显示颜色变化方向。图片取色、目标调整、复制粘贴、用户命名预设和新调色算法仍属后续范围，撤销 / 重做与复制粘贴入口已占位并标明规划状态。

对比是本轮明确修改的交互：四端点按同一矩形分屏图标开关对比，并记住上次使用的方式；桌面图标旁的下拉箭头、移动端长按图标或画面底部的切换选择“并排 / 分割线”，与 Windows 现有的对比菜单一致。画布高而窄时并排改为上下排列；分割线和“调整前 / 调整后”标签都限制在照片范围内。不打开对比时，按住照片（桌面按住反斜杠键）临时查看调整前。模式变化不修改照片参数，也不改变照片区或调整区高度。该方案扩展了各端原有的不同对比方式，不能写成四端当前已经全部具备。

桌面自动下载与安装更新是独立规划，附在两端设计中；保留已有检查更新概念，自动安装初始关闭，演示下载准备、等待任务完成及失败重试。更新提示参照 Mac 常见的 Sparkle 样式，只放版本、内嵌发布说明和“跳过此版本 / 稍后提醒 / 安装更新”；长期设置在“设置 → 软件更新”。此设计不确定具体安装框架或签名方案，也不表示桌面端已实现下载与安装。

## 文件职责与复用边界

| 文件 | 维护内容 |
| --- | --- |
| `manifest.js` | 设计版本、评审/确认/实现状态、平台入口与素材来源；不维护功能验收结果 |
| `shared/model.js` | 六组映射、工具名称、色域、参数示例、场景说明、尺寸目录与配方示例；这些是原型数据，不是新的跨端参数契约 |
| `shared/screens.js` | 完整界面/状态清单、稳定 ID、适用平台、功能来源与原生依据；设计板和覆盖表从同一清单生成 |
| `shared/icons.js` | 统一的 SVG 语义图标目录，记录已核对的原生图标名称和本轮统一决策；未知图标直接报错，避免静默换成设置图标 |
| `shared/tokens.css` | Web 原型的语义颜色、字号阶梯、间距、圆角与点击目标，以及各平台和大字号的覆盖值；对应已有设计规则，不取代 SwiftUI、Compose、AppKit 或 WPF 的原生令牌 |
| `app.css` | 共用布局及 `.ios` / `.android` / `.macos` / `.windows` 的平台差异，横屏与大字号重排 |
| `app.js` | 设计状态切换、临时模拟值、重置确认、草稿退出和更新流程演示；不连接应用 |
| `flows.js` / `flows.css` | 导入、外观管理、单张/批量导出、任务、设置与系统集成界面的交互和布局 |
| `index.html` / `preview.html` | 评审导航与画布；四端入口传递平台、状态和字号参数，不复制一套原型源码 |
| `coverage.html` | 可点击的界面覆盖表，显示各平台功能、状态入口与原生来源 |
| `scripts/review.cjs` | 可重复的浏览器检查与截图导出；验证分组布局与收起、已调整标记、双向滑杆填充、对比开关与方式选择、裁切框拖动、处理状态不移动布局、流程返回与平台适配 |

原型复用已入库的胶片/配方 artwork，以及旧设计稿中的照片区域，不复制这些图片。具体来源和裁切视口记录在 `manifest.js`。照片与参数不会联动，示例直方图也不来自真实计算；它们仅用于评审空间分配，不能用来评估图像处理质量。

## 状态与交互检查

设计板按“功能范围 → 界面状态”直接定位全部已登记界面；也可从原型内真实入口进入流程。尺寸包括 320 pt/dp 窄屏、手机竖/横屏、平板、桌面标准/紧凑窗口，并可切换大字号。覆盖表的“已有功能”描述能力来源，所有新稿仍按资产元信息进入评审，不将 HTML 截图当作原生实现证据。

- 切组不改参数；切色域保留各自设置。重置统一收在调整区右上角菜单，按范围从小到大排列（当前工具或颜色 → 本组或全部 HSL → 全部调整），影响整组或全部的项需确认；双击参数名称或滑杆恢复单个值。
- 每项参数一行：名称在前、滑杆居中、数值在后。输入框里只有数字，EV、K、%、° 等单位用次要文字显示在框外右侧；单位位置每行保留，上下行数值框对齐。不显示默认值、范围等说明；只有不好理解的项（如暗角的高光保护、降噪的粗色斑抑制）在下方加一行短说明。大字号时名称与数值一行、滑杆另起一行。
- 开 / 关设置统一使用开关组件；两三个互斥选项用分段控件，选项多或文字长时才用菜单。照片多选和“我已核对”确认仍用勾选框。
- 调整区高度固定：切换分组、组内工具或出现草稿按钮时，照片区与调整区大小都不变，内容在参数区内滚动。
- 滑杆填充从默认值画到当前值：双向参数从中点向两侧，单向参数从起点开始。数值未改动时为中性色，改动后为黄色；黄色不用于重置、自动等次要操作。
- 精确值先留在本地输入草稿，取消不改原值。iOS 单列包含合法值；桌面输入校验范围并保留 Enter / Escape 操作。
- 几何/镜头保留本地草稿及固定的取消/应用行。未变化时应用不可用；有变化离开时提供应用、放弃、继续编辑。应用或取消后按现有约定回到曝光；草稿存在时导出禁用。
- 预览更新仅在照片区域顶部叠加 2 px 细线，不显示突出处理框；进度不参与布局，显隐均不改变画布、调整区和工具高度。普通图片的相机专属参数说明不可用原因；保存失败仍持续说明“调整未保存”并提供重试。
- 更新窗口限制背景交互，下载失败可重试或手动下载；等待任务时不强制结束导出。点击安装只演示入口，不执行真实替换或重启。
- 流程窗口有上一级时标题栏只给返回，顶层只给关闭；移动端顶层的“取消”由标题栏关闭代替，桌面窗口用底部按钮与 Esc。打开对话框时焦点落在对话框本身，不预先落在关闭或破坏性按钮上。
- 单张导出保留平台支持的格式、尺寸与保存位置；iOS 是 JPEG 到图库、渲染型 DNG 到文件，其他端还支持 16-bit PNG。导出完成与保存失败分别可定位。
- 批量目标初始为空。来源设置在进入流程时冻结；选择、检查目标效果和返回不丢选择，确认页不提供逐张调节。运行、停止、完成、部分失败、取消、恢复、重新授权、移动端不确定保存结果和 iOS DNG 文件保存均有独立状态。
- Android 的相册与桌面的文件树分别呈现。完整设置应用、目录读取/移除仅登记桌面；iOS 不增加不存在的关于/开源许可页，Android 保留现有关于、检查更新与许可入口。

以上是待评审设计行为，浏览器检查不能证明原生触感、无障碍、渲染性能、持久化或安装链路已通过验收。

## 打开、修改与评审

可直接打开 `index.html`；也可从仓库根目录运行：

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8766/docs/design/editor-workspace/`。所有图片与脚本使用相对路径，不依赖作者机器的绝对路径、不下载字体或前端依赖。入口支持 `?scene=hsl&largeText=true`；完整状态名以 `shared/screens.js` 为准，尺寸目录以 `shared/model.js` 为准。

有现成 Playwright 工具环境时，可以重复导出所有登记界面并运行浏览器检查：

```sh
node docs/design/editor-workspace/scripts/review.cjs
```

脚本默认连接上述本地预览服务，截图和检查结果写入系统临时目录。可通过 `RAWLAB_DESIGN_URL`、`RAWLAB_DESIGN_OUTPUT` 和 `RAWLAB_DESIGN_PLAYWRIGHT` 分别指定预览地址、导出位置及现有 Playwright 包路径，不向应用增加依赖。生成物不是设计源文件；建议导出到被忽略的 `screenshots/` 或外部评审目录。

后续修改流程：

1. 先读本文件、`manifest.js`、覆盖表、根设计基线与相关平台来源，在本目录增量修改；共用分组/状态改模型，跨端颜色改令牌，图标改统一目录，平台布局改对应 CSS 规则，避免四端复制后分叉。新增界面先登记稳定 ID、平台与来源，再补实际画面和入口，不用空链接计为覆盖。
2. 设计发生实质变更时递增 `designVersion`、更新日期并设为 `in_review`；在下方决策表说明新增或改变的行为及原因。小的拼写修订不必建立新版本目录。
3. 在四端代表尺寸检查相关正常、空、忙、错误、禁用和草稿状态；验证返回、精确值取消、重置作用范围和键盘可达性。浏览器截图放本目录被忽略的 `screenshots/` 或外部评审目录；本地过程和检查结果写 PR 描述。
4. 用户确认后在 `manifest.js` 记录确认依据并设为 `approved`，再更新相关需求/技术方案与 `DESIGN.md` 的已确认规则。需要同步 impeccable 元信息时按其文档化流程处理，不把原型 CSS 灌入原生 schema。
5. 各端落地时按平台记录证据；`implementation` 与设计批准状态分开维护。只完成一端时不能把四端标记为已实现。

## 设计决策

| 决策 | 原因与范围 |
| --- | --- |
| D01：六组常驻、组内工具在其上方展开；保留桌面底部调整区 | 解决工具增长后的平铺问题，又不增加“进入 / 返回”层级：跨组切换一次点击，面板可收起把空间还给照片。r3 起替代 r2 的整页进入与返回 |
| D02：只组织已有参数，混色器先做选择、精确值与重置 | 与 roadmap 第一步对齐，后续算法和复用能力不会伪装成已可用功能 |
| D03：四端共用信息结构，保留原生控件语义与尺寸重排 | 避免数据与导航分叉，同时保留值轮、Material 输入、AppKit/WPF 键盘操作差异 |
| D04：桌面自动安装更新独立交付 | 不阻挡分组、复制粘贴和用户预设；安装前必须处理编辑与任务，失败可恢复 |
| D05：设计源文件持续维护，截图按需生成 | 下一轮从可编辑源文件修改，评审状态有唯一来源，减少复制图片与失效路径 |
| D06：竖屏分组单行横滑，侧栏六组一次可见 | 竖屏与大字号保留可读宽度并水平滚动，边缘渐隐提示还有内容。Android 普通字号复用原工具条 80 dp 单项宽度、8 dp 间隔、48 dp 图标环与 24 dp 图标。横屏侧栏未展开时为 2×3 宫格，展开后为六列紧凑行，不再横滑。四端已调状态统一用小点加可访问名称，避免外语文案被截断 |
| D07：固定顶部细线表达预览处理 | 进度叠加而不参与布局，避免处理显隐引起高度变化；无障碍仍能获得状态 |
| D08：统一语义图标、恢复几何图标按钮 | 对比使用左右对称的矩形分屏（外框加中线，r4 去掉单侧填充）；“中性”和“无配方”使用同尺寸图标块；旋转保留原有转动方块/回转箭头语义，翻转保持各自方向，按钮具备标签与提示 |
| D09：对比点按开关、方式另选，并支持按住看调整前 | r2 的单按钮三态循环无法预知下一步，关闭前还必须经过分割线；r3 改为点按开关并记住方式，方式由菜单、长按或画面内切换选择。手机竖屏并排改上下排列；查看方式变更不写入照片参数 |
| D10：补齐当前应用完整界面 | 仅覆盖现有能力和本轮提案，不把后续复制粘贴、用户预设、颜色分级等画成当前功能 |
| D11：黄色只表示选中、已改动和进度 | 与 DESIGN.md 的功能色规则一致；重置、自动等次要操作改为中性灰，未改动的数值不再显示黄色 |
| D12：重置收进一个菜单，按范围排序 | 原先标题、当前颜色和每行三层重置同屏，且都用强调色；r4 起单值重置改为双击名称或滑杆，整组和全部需确认 |
| D13：滑杆从默认值填充，HSL 轨道显示颜色方向 | 修正 r2 从最左端填充导致 -12 看似 44% 的误读，恢复旧设计稿的中点填充；色相、饱和度、明度轨道帮助判断拖动方向 |
| D14：“精细”每个面板一个开关 | 原生“精细”是拖动灵敏度降为四分之一，每行重复一个按钮增加噪音；仍只在移动端提供 |
| D15：裁切以在照片上拖动为主 | 裁切框四角和四边可拖动并压暗框外，数值裁切收进“精确裁切”；与 iOS 已有的裁切拖动手柄规则一致 |
| D16：更新提示与更新设置分开 | 提示只处理本次是否安装，提供“跳过此版本”；长期的自动检查与自动安装放在“设置 → 软件更新” |
| D17：为第二阶段预留入口 | 撤销 / 重做放在顶栏（Windows 同时在“编辑”菜单），复制 / 粘贴调整在“更多”菜单，“我的预设”在外观组；均标明规划中，不作为当前功能 |
| D18：Windows 稿对齐现有 WPF 外观 | 增加经典菜单栏、RAWLAB 字标、右侧设置与关于、WPF 方形滑块、5 px 按钮圆角和 Segoe UI / 微软雅黑字体，避免直接沿用 Mac 外观 |
| D19：参数单行，删去默认值与范围说明 | r4 用户评审：原先名称 / 数值、滑杆、范围说明分成三行，占高且噪音多；单行后 HSL 三轴无需滚动，说明只留给不好理解的项 |
| D20：开关组件与分段控件 | r4 用户评审：开关不用下拉菜单或勾选框。桌面降噪与原生 Mac 一致，为“降噪”开关加预设分段，一行排完；旧版 FBDD 只在旧记录中出现，不放在主面板 |
| D21：调整区高度固定 | r4 用户评审：切换工具时面板高度不同会让照片跳动；手机统一参数区高度并在内部滚动，草稿按钮占用参数区而不是额外加高 |
| D22：照片信息回到左上角 | 恢复原有的“点击依次显示文件信息、拍摄参数、收起”，平时只显示信息图标；白平衡等细节进信息层，不常驻画面 |
| D23：可关闭照片四周留白 | 在缩放与显示中提供“照片四周留白”开关，关闭后照片贴边占满预览区；默认保留留白 |
| D24：移动端单击进入纯预览 | 单击照片区隐藏其他界面，再单击恢复；按住仍查看调整前；裁切编辑时不触发 |
| D25：四端直方图统一为 RGB 三色 | 与 Mac 原生一致：R、G、B 分开绘制，重叠处按加色混合。iOS 原生目前是亮度直方图，落地时需要改 |
| D26：iOS 刻度尺始终铺满 | 视窗以当前值居中但不越过参数范围，值在最小或最大附近时指示线移向边缘，避免从 0 开始的参数只剩半边刻度。与 iOS 原生“指示线固定居中”的做法不同，落地时需要改 |
