# Sony 无线联机拍摄

日期：2026-11-10。版本：2。状态：Android 原生入口、单一会话 owner、原件回传与持久恢复已接入；正式联机端到端设备验收尚未全部完成。
设计基线：`d821615e2318b2806032aaefd56376e81afbc5e7`。

## 目标与范围

在 RawLab 中查看相机实时画面、按快门、自动接收新照片，并能在机身按快门后接收照片。
目标为 Sony α7C II（`ILCE-7CM2 / 2.00`）和初代 ZV-E10（`ZV-E10 / 2.02`）与 Android 10+；验证设备沿用 Pixel XL。
照片继续保存到系统媒体库，按已有拍摄日期目录规则归档，从 RawLab 相册继续编辑。

用户已选择上述范围。首版只支持静态单张拍摄，曝光参数、对焦模式和驱动模式在机身调整；
不加入曝光参数面板、触摸对焦、连拍、B 门、视频、多机、后台持续接收或其他平台。
自动对焦是否由单次快门序列触发，以及机身快门是否在遥控会话中仍可用，必须由目标机型实验确认。
这里的持续会话是多次独立单拍，不承诺相机连续驱动模式的连拍吞吐或无遗漏。
只实现机身快门后的传图、只显示历史照片或缩略图，均不算完成本轮目标。

## 现状与方案选择

设计前的 Android `SonyCameraConnection` 用 BLE 初始化后向 `CC08` 写入 `01` 启动传图连接；
`SonyMobileSession` 建立 PTP/IP 双通道，使用 `0x923C/0x923D/0x923E` 列表、下载和预览。
事件线程目前只响应探活并校验事件外形，不向业务层分发拍摄事件；命令层也没有主机发送数据阶段。
`CameraImportViewModel` 按固定选片队列传输，整批持有会话锁，不适合直接插入取景轮询。

| 路线 | 收益与限制 | 决定 |
| --- | --- | --- |
| 在现有手机连接上增加经过验证的遥控 profile | 复用 BLE/Wi-Fi、权限、媒体库及编辑身份；需要先确认模式切换、控制命令与拍后对象语义 | 首选，先实验后接产品 |
| Android 移植桌面 PC Remote + SSH | 已有桌面传图认证基础，但不是已验证的手机遥控流程，增加认证与网络设置步骤 | 只作协议比较；首选失败时重新评估，不静默切换 |
| 仅监视新照片或接收 FTP | 能解决部分机身拍摄回传，但无法满足实时取景和远程快门 | 不作为本轮完成方案 |

这是当前实现选择与实测边界。2026-11-10 用户要求取消已验证机型的连接准入作用，
新版按 [协议选择规则](sony-wifi-design.md#31-协议配置的选择规则) 与实际能力处理其他型号的连接尝试。
现有精确型号 profile 仍是源码现状，后续需要调整；设备广告一个操作码不能代替命令语义验证。

## 已知证据与尚缺证据

Sony 的 [Creators' App 遥控说明](https://helpguide.sony.net/di-app/ca/v1/en/contents/CA_remote_shooting.html)
确认官方 App 经蓝牙建立 Wi-Fi 连接并显示 live view。
[导入说明](https://helpguide.sony.net/di-app/ca/v1/en/contents/CA_import_from_camera.html)
将导入与遥控区分，注明传图期间可用的机身拍摄不包括远程拍摄。不能把传图连接成功外推为遥控可用。
[遥控界面说明](https://helpguide.sony.net/di-app/ca/v1/en/contents/CA_camera_screen.html)
指出默认自动传回的可能是 2M 图像；预览成功不证明原件回传成功。

[α7C II 遥控拍摄设置](https://helpguide.sony.net/ilc/2360/v1/en/contents/201h_remote_shoot_setting.html)
支持设置保存目的地、回传大小及 RAW+JPEG/HEIF 表示。设计要求机身存储卡保留原件，
并核实回传表示；不自动切到只保存于手机，也不静默修改用户的持久相机设置。

### 首个已验证 profile

独立 [Android 实验包](../../../tools/camera-transfer/android-connect/README.md#无线联机拍摄实验) 已在
`ILCE-7CM2 / 2.00 / Smartphone Connection / Pixel XL / Android 10` 核实：

- BLE `CC08=01` 后，同一手机 Wi-Fi 链路可执行 `0x9201` phase 1/2、`0x9202(0x12C,1)`、phase 3；
  没有进入 `0x9212` contents-transfer mode，也不需要桌面 SSH。
- `0x9209` 提供保存目的地、驱动和 `D278` HTTP 取景地址；该设备输出可解码的 640×480 JPEG 取景帧。
  取景流与 PTP 卡内原件传输可同时运行，帧不是系统媒体库原件。
- `0x9207(D2C1/D2C2)` 的半按/全按/释放序列能触发单拍，机身快门也能在同一遥控会话中拍摄。
- 两种快门的新 ARW 均可通过卡内内容增量发现、`0x923D` 下载；原只读客户端另建会话取得同一对象，
  大小与 SHA-256 一致。当前证据不是独立读卡器比对。
- 机身操作时可能收到 `0x923C → 0x2005` 的完整错误响应，取景流仍继续；实验加入有上限的读卡等待，
  保留基线，不重试快门。具体机身状态转换的恢复覆盖仍需产品接入时补齐。

相机当时由用户设置为双端保存、原始大小、单拍；实验只读取这些设置，不写入。
本轮使用 ARW 和 RAW+HEIF 设置；仅 ARW 原件完成验收，HEIF 未接入，JPEG 原件尚未实机验收。
上述是独立实验的协议证据；原生产品验收与协议实验分别记录，不据此推断其他固件或文件表示。
协议代码依据固定在 Apache-2.0 的
[alpha2go v0.3.0](https://github.com/Knallli/alpha2go/tree/02883425c9445c653b2950210187cdd1547320c2)，
协议参考与声明见 [第三方说明](../../../tools/camera-transfer/THIRD_PARTY_NOTICES.md)。

### ZV-E10 的独立 profile

初代 `ZV-E10 / 2.02` 使用 [Imaging Edge Mobile 的连接流程](https://support.d-imaging.sony.co.jp/support/cscs/l/iemconnect/e10/index.php)。
当前实现让用户在相机打开「网络 → 智能手机连接 → 连接」，在系统 Wi-Fi 选择相机热点后返回 RawLab。
已配对蓝牙不代表已经取得 Wi-Fi 凭据；本机没有验证到 α7C II 的 `CC08` 启动路径，不能宣称支持自动交接。
Android 必须保留无互联网的相机网络。应用只把相机流量绑定到选定 Network，不修改全局默认网络。

- 媒体导入使用独立的只读接口 `SonyLegacyImportSession`，完成遥控握手后进入 `0x9212` 内容模式，
  由 `0x1004/0x1007/0x1008` 枚举卡内对象、`0x1009` 下载完整原件；该接口不暴露快门。
- 联机取景使用 `D278` HTTP 流，实验得到 640×424 帧。软件单拍已分别验证 MF 与 AF，机身单拍也已验证；
  RAW+JPEG 的 host 回传与随后独立获取的卡内原件大小、SHA-256 一致。
- 进入内容模式会使原遥控会话不能可靠触发拍摄，即使命令返回成功。每次卡内核对/下载后关闭旧会话，
  明确退出内容模式后重新建立遥控连接，并等待初始化稳定；首次进入内容模式也等待遥控初始化。
  此时界面明确暂停取景和软件快门。
- `D215` 只作为临时 host 图像可取的线索。临时对象可为缩小图，不能直接发布为原件；
  产品始终重新枚举卡内持久对象并下载。只有同名、同大小且唯一的对象追加 host 摘要比对。
- 该手机模式下，机身菜单显示双端保存且实际双端均有文件时，`D222` 仍返回 `1`；
  不套用 α7C II 的位含义。连接页要求明确确认双端保存，不写入机身的保存、对焦或驱动设置。

当前实现对固件和型号精确匹配；ZV-E10 II 不属于这个已验 profile。HEIF、视频与其他固件未在该 profile 验收。
这些记录不构成新版产品的机型白名单；其他型号仍应按实际协议能力尝试连接，不能据此声称已经验证其功能。
ZV-E10 的缩略图请求有协议回归覆盖，设备验收需与原件传输分别判断。

## 会话与控制合同

同一时刻一台相机只有一个会话 owner。现有选片导入和联机拍摄互斥；切换前停止当前命令调度、
保留已保存结果并关闭旧会话。连接代次约束所有回调，旧事件、迟到帧及连接结果不能进入新会话。

状态顺序：`未连接 → 连接中 → 核实能力/建立基线 → 就绪 → 拍摄/接收 → 就绪`。
断网、后台、用户停止进入暂停；重连先重新核对相机和未完成对象，再由用户恢复，不自动拍摄。
显示就绪前关闭软件快门入口，明确尚未开始接收；准备期间的机身照片可之后走普通导入。

控制合同：

- 首版单次快门请求只允许一个在途；采用目标 profile 已验证的按下、释放与对焦时序。
  相机处于不支持的驱动模式时提示用户在机身调整，不自行写入单拍模式。
- 发送快门前记录本地请求；命令确认、相机拍摄确认、原件保存完成是三个独立状态。
  命令超时或断线后显示“拍摄结果待确认”，恢复只接收新对象，不自动补发快门。
  同一连接中已确认的请求在新批次完整保存后结束收片等待，但不把文件归因为某次软件快门。
  跨连接遗留的未知请求不会因旧任务接收完成而自动消除；核实机身后可由用户开始新会话。
- 用户离开或取消不能撤销已发生的曝光。若 profile 有按下状态，必须按已验证协议释放；
  无法确认释放时关闭会话、提示检查相机，不继续发送控制命令。
- 当前相机不支持某能力时清楚提示；不以下载缩略图冒充实时取景，不以刷新旧照片冒充拍后接收。

## 实时取景与传输调度

使用一个串行命令调度器处理相机事务，事件读取独立运行。不能同时从 command socket 读多个事务。
优先完成快门释放和关键控制，再处理新对象确认/原件传输；live view 为可丢弃的低优先级请求。
同一时刻最多一个取景请求，显示最新完整帧，不积压帧队列。

如果已验证 profile 通过 `D278` 提供独立 HTTP 取景流，流读取与 PTP 命令分开，
只连接所选相机网络/地址，拒绝重定向，URL 中的会话参数不写日志。
该流与下载可以并存时无需逐帧竞争 PTP 命令锁；解码和显示仍只保留最新帧。

初始取景请求或解码显示上限为 10 次/秒；独立流可丢弃多余帧，实际刷新率按相机和传输情况自适应，
这不是对设备性能的承诺。
帧字节、尺寸、解码内存有明确上限，拒绝损坏/截断帧。取景不写入 MediaStore，不走 RAW 显影。
单次坏帧可丢弃，事务错位、超时或断流则关闭失效会话，避免把迟到数据读作下一个事务。
超过正常帧间隔没有新帧时标注画面暂停，不继续显示“实时”。

只有实验证明可以交错事务时，才在原件分块之间取景。否则原件传输期间暂停取景并显示进度，
完成后恢复；首版在此期间禁用软件快门，继续登记机身新照片事件。不能为流畅画面丢弃原件。

## 新照片发现、保存与恢复

就绪前建立当前卡内对象基线，并接好事件读取；基线照片不自动导入。
新对象事件只是发现线索，必须读到完整元数据和可传输的原件后才入队。
机身与软件快门走同一条发现/传输链路；不要依靠“发送快门后最新的一张”匹配结果。
重复事件合并，乱序事件允许，不能假定一条事件等于一个文件或一次快门。

首版按相机实际文件格式回传 ARW/JPEG 原件；RAW+JPEG 两个文件分别校验、保存和显示状态。
有可靠共同拍摄标识时可合为一组显示，否则保留独立条目，不凭相邻文件名或时间强行合组。
HEIF 的接收和编辑不沿用尚未验证的 JPEG 成功状态；遇到不支持的格式明确提示。
2M 图或内嵌预览只作临时审片，必须与原件状态区分。

相机存储卡始终作为本轮恢复来源。若新拍结果只提供会覆盖的临时缓冲句柄，必须先证明能够对应到
持久卡内对象；否则不能保证会话内多次机身单拍的恢复，不开放自动接收产品入口。
事件缺口或队列压力触发卡内增量核对，不能只靠最后一个时间戳或文件名判断新增。
同时间戳、多表示、旧事件、换卡、文件编号复用均不能关联到错误原件。
不能证明恢复范围时暂停并让用户从相机挑选补传，不能自动把整张卡当作新拍照片导入。
空卡可以开始新会话；若暂停前尚无基线或已登记批次作为身份锚点，则不能自动恢复。

会话记录冻结目的地规则并登记已发现文件、未完成传输和已发布结果；仅保存非敏感元数据，
不持久化 Wi-Fi 密码或跨会话直接复用句柄。重连重新枚举并核对来源，完整文件按摘要去重。
沿用 `CameraImportStore` 的原件校验、MediaStore pending/发布、去重及编辑身份；
用小批任务接入现有发布事务，新增会话记录只负责发现与任务关联，不另建持久原件库。
一次性临时字节保持现有清理规则；已发布原件永不因会话停止而删除。

具体所有权与崩溃顺序如下，避免让现有固定队列承担动态追加：

- 相机导入与联机拍摄通过同一个应用级存储 owner、同一把存储锁访问完整任务集合。
  不允许两个 ViewModel 各建一个可清理相同目录的 Store。切换模式先使旧代次失效，
  等待旧任务退出和已准入发布完成，再交接所有权；仅在没有活动下载/发布时调用 `load()`。
- 每个有界小批建立独立、内容固定的 `CameraImportJob`；活动任务不追加 items。
  事件先登记到会话的待调度发现集合。会话 UI 聚合关联任务的文件状态，任务记录负责发布真相。
- 在同一存储 owner 下先持久化发现项及其预留的唯一批次 ID，再用此 ID 幂等创建任务，
  记录关联后才开始传输。重启用预留 ID 查找并核对已有任务，不能重新随机生成任务或重新拍摄。
  崩溃在任务创建前则继续创建；创建后关联落盘前则接回已有任务；发布后按既有事务恢复结果。
- 先恢复完整 Store，再对账会话索引；会话的“已保存”从任务发布结果派生，不单独维护第二份成功真相。
  新增关联字段保持旧任务可读取，未关联会话的历史选片任务按原行为处理。

磁盘不足、相机忙或待接收量超限时停止软件拍摄并显示待接收状态。应用不能阻止机身快门；
保留可恢复的发现进度，在范围无法核实时明确提示可能有待补传照片，禁止静默丢队列。
每次接收最多 64 个原件或 2 GiB；达到预算后保留固定批次，恢复时先处理未完成项，避免超限反复停在同一位置。
α7C II 约每 1.5 秒核对卡内增量；ZV-E10 有 host 线索时立即核对，软件快门后即使缺少该线索也主动核对一次，
空闲时约两分钟完整核对，并重建遥控会话。
ZV-E10 的逐对象核对会随卡内数量变慢，在此期间暂停取景；不能靠复用旧会话句柄跳过来源验证。
原件在会话开始、停止和编辑交接时重新核实；活动接收不反复扫描、散列整个历史媒体库。

## 用户交互

沿用当前 Android 深色主题与黄色强调色，在相机入口增加“联机拍摄”，与“从相机导入”并列。
布局参考 Sony 官方 [Creators’ App 遥控页](https://helpguide.sony.net/di-app/ca/v1/en/contents/CA_camera_screen.html)
和 [Imaging Edge Mobile 纵横屏界面](https://support.d-imaging.sony.co.jp/app/iemobile/en/instruction/1_1_smartphone_display.php)：
竖屏取景在上、中央大快门在下；横屏为左侧取景与右侧控制栏。不复制尚未支持的曝光、对焦、视频或连拍控件。
连接流程复用已配对设备和系统 Wi-Fi 确认；协议名称、端口和命令码不进入日常界面。

```text
返回               联机拍摄                 结束
α7C II · 已连接                    拍摄设置在机身调整

              [ 相机实时画面 ]
            传输期间显示取景暂停

最近照片 [预览] [预览] [预览]        已保存 3 · 待接收 1
                  [ 拍摄 ]
              查看已保存 · 保存位置
```

新照片完成后更新最近照片条，不自动离开拍摄页、不抢占正在查看的旧照片或编辑器草稿。
点已保存照片进入独立审片，支持切换、双指缩放和复位；预览明确标注，不冒充全分辨率显影。
“拍后审片”默认关闭，开启后仅在未查看旧照片时打开新照片。点“编辑”先暂停联机拍摄，再走现有草稿门禁和稳定媒体 URI。
返回时用户主动恢复会话。最新照片的预览、原件接收中、已保存和失败分别呈现。
保存位置沿用 [Android 系统媒体库合同](android-media-library.md)，按拍摄日期分目录。
App 进入后台或锁屏时暂停控制与接收，保留已保存照片；仅活跃前台会话保持屏幕唤醒。

## 实施阶段与完成条件

1. **手机遥控协议实验**：在独立 Android 实验包确认启动/握手、完整取景帧、软件单拍、机身单拍、
   快门释放、对应原件回传和退出。记录型号/固件/模式，读卡或已验证内容接口独立取得同一对象，
   比较大小与 SHA-256。RAW 与 JPEG 分开验收，不用预览代替。失败时停在具体能力缺口。
2. **协议与会话模型**：新增独立遥控 profile、主机发送数据阶段、事件解析、代次和串行调度。
   本机 responder 回归覆盖分包、事务错位、事件重复/乱序、帧损坏、相机忙和未知拍摄结果。
3. **回传与恢复**：新增会话发现记录，接现有发布事务，验证 RAW+JPEG、同名不同内容、失联、
   后台准备窗口、发布瞬间死亡、重连换卡及媒体库外部修改。恢复不重拍、不重写已有原件。
4. **产品交互与设备验收**：加入原生入口、取景、快门、最近照片及恢复提示，同步六语文案。
   运行受影响本地 UI 测试，然后在 Pixel XL 上操作真实页面，完成两种快门到相册编辑闭环。

每个阶段由本功能 owner 集成，协议/持久化稳定后再接 UI；不同时维护两套媒体库发布逻辑。
单次日志、截图、实验数值、命令和 PR 验证清单放临时产物或 PR，
本文件仅维护长期合同；编译、模型测试、设备 UI、实体相机协议分别报告。

完成本轮功能至少需证明：持续取景、软件单拍不会自动重复、机身单拍可发现、原件完整保存、
停拍/重连可恢复、相册编辑身份一致、原有选片传图回归通过。其他机型、固件与平台仍标未验证。
分支 push、PR、合并和发布继续遵循仓库授权规则；前一轮 PR 的合并授权不延伸为本轮发布授权。
