## 3. 第一阶段收尾（ITER-01）

### 3.2 MCP 接入

- 提供本地 stdio MCP server，暴露 `capabilities`、`validate_recipe`、`image_info`、`render_preview`、`export_photo` 五类工具；工具输入使用明确 schema，不接受任意命令行或 shell 文本。
- 转调已经存在的 CLI；同一配方直接调用 CLI 与经 MCP 调用得到相同字段、错误类别和像素结果。预览返回可访问的文件结果与必要尺寸/来源信息，不用缩略图冒充最终导出。
- 启动时指定 CLI 路径、允许读入目录与允许写出目录，拒绝越界/无效路径、输入覆盖和不支持参数；不引入登录、云目录、远程 HTTP 服务或新的图像算法。
- 支持请求取消、进程退出、超时、损坏配方、未知能力、找不到外观/源照片及输出失败；日志不污染 stdio 协议流。失败不得留下看似成功的最终输出。
- 安装/配置说明包含 CLI 与 server 版本匹配、客户端配置和 smoke test；不用“server 启动成功”代替实际渲染与导出验收。

## 5. Lightroom 式复制粘贴与编辑历史（ITER-03）

### 5.1 选择与冻结

提供复制调整、选择要复制的调整、粘贴调整；可粘到一张或多张照片。范围为“全部 / 仅已修改 / 自定义”，组可展开到独立项，HSL 可到色域/轴；几何和镜头不默认包含，“全部”或显式勾选才包含。

“仅已修改”使用源照片的有效默认，不依赖操作历史。复制冻结选中字段、模式、固定值、外观身份和数据版本；复制后继续编辑、切图或删除原照片不改变剪贴内容。相机校准、自动匹配结果、照片身份、EXIF、zoom/pan 与临时草稿不复制。未应用草稿先处理，不能复制尚未提交的临时状态。

来源有草稿时提供应用并继续、放弃并继续、继续编辑；应用必须保存成功才复制/保存预设。目标有草稿时逐张处理，可明确跳过目标或取消操作；失败保留草稿并说明阻挡，不静默覆盖。粘贴历史的前态取自草稿处理之后，之前用户已确认的草稿应用仍是独立编辑。单独“检查目标草稿”只处理用户明确选择的草稿决定，完成后返回预检摘要，不代表确认粘贴；由“应用并保存”发起的预检才可继续本次提交。全部目标被排除或跳过时说明没有可处理目标，不显示成功，也不创建粘贴历史或导出任务；重新选择和返回保持原操作种类。

### 5.2 应用与失败

- 粘贴前显示来源、目标数量、范围及不兼容项；只替换所选项，未选项保留，重复粘贴不累加。每次新操作重新确定来源、目标与草稿决定；完成、取消、返回操作入口或关窗后，不将预设内容、跳过目标或待执行动作带入下一次操作。剪贴内容、集合选择与已保存历史独立保留。
- 拍摄时 WB、自动曝光基准/镜头匹配逐张解析；固定自定义值照值应用。RAW/普通图片按现有相机专属约束处理，不把源照片的校准数据带到目标。
- 外观缺失、未来版本、目标不支持的项不得静默丢弃。先报告不兼容项并让用户取消或明确选择跳过；成功/跳过/失败逐张列出，不能把部分应用叫全部成功。
- 对每个目标按稳定身份保存，目标当前有脏草稿时先处理；保存失败保留可重试结果，不能仅内存变更就标记已保存。

### 5.3 会话历史

拖动结束、数值提交、范围重置、胶片/外观选择、大师配方、降噪开关/预设、自动曝光、白平衡模式、几何/镜头应用、粘贴和批量同步均从同一提交入口形成明确历史项；连续一次拖动只记一次。没有变化、取消和保存失败不创建成功历史；失败后重试成功只记录一次。导航、复制、选择范围、临时查看和导出不记为照片参数编辑。

单张撤销/重做只处理该照片；多目标粘贴/同步为一个事务，历史记录实际成功目标及前后快照，撤销不动失败目标和无关修改。若目标后来被独立修改，撤销前报告冲突并要求确认处理范围，不能静默覆盖新编辑。新编辑清除相关 redo 分支；撤销不清剪贴内容。首批历史限当前会话，重启仍恢复已经保存的参数，不承诺跨重启历史。

单张编辑器的撤销处理当前照片的历史分量；批量结果中的“撤销本次粘贴/同步”显示实际目标数量，处理事务尚未撤销的成功目标。两者共享记录，不会重复撤销同一目标。输入框仍在编辑时，系统文本撤销优先，不把撤销一个字符变成撤销照片调整。

## 6. 用户调整预设（ITER-04）

- 外观组新增“我的预设”，保存当前已提交调整，命名、应用、重命名、删除；与内置配方、导入外观和每照片自动保存分别呈现。
- 保存时复用复制范围；默认名称可编辑，拒绝空白，重名要求明确选择另存或覆盖。覆盖/删除需确认；重命名不改变预设内容和引用 ID。新预设使用唯一稳定 ID，不以列表长度、位置或名称生成；删除其他预设后再创建，不得影响已有预设的应用、重命名或删除目标。
- 内容独立保存包含的字段、值、模式、外观引用与版本，不依赖原照片存在。应用走同一按项粘贴、持久化和历史事务；相同内容通过预设和剪贴板应用应得到等价参数。
- 首批本机持久化，重启可用；损坏、缺外观、未来版本、部分不支持与粘贴使用同一提示。文件失败不损坏原预设，不伪装保存成功。
- 不包含云同步、Adobe 预设格式导入或在线市场。可扩展格式容纳本轮所有新参数；旧预设省略新字段时保持原语义。

## 7. 黑场、白场、鲜艳度（ITER-05）

新增三个独立控制，默认均为 0、UI 范围均建议 `[-100,100]`；范围与算法作为本方案待评审选择，不能宣称与 Adobe 数值等价。

- 黑场：负向压低暗端、正向抬起暗端；白场：正向提高亮端、负向压低亮端。任意合法组合（含双项极值）均保持灰阶非递减，中间调连续，端点/高光不过早硬截断，不等同于重复现有阴影/高光。
- 鲜艳度：正向优先增强较低饱和颜色，降低已高饱和颜色和常见肤色的过度变化；负向逐步降低彩度。与普通饱和度分别控制，灰色不凭空染色。
- RAW 与已有支持的普通图片均可用；所有字段进入核心、四端、保存恢复、复制/预设、Agent 与逐张导出。全零必须精确走原路径，不改变旧照片和旧配方。

## 8. 三分区颜色分级（ITER-06）

颜色组提供阴影、中间调、高光三个明暗分区，各自色轮与精确色相/饱和度。建议色相 `0...360°`（360 与 0 等价），饱和度 `0...100`，默认饱和度 0；三个分区平滑重叠，不能以硬亮度阈值产生色带。

提供单区重置、整工具重置、分区切换和已调整标记。当前分区选择不修改其他分区；无彩度时色相可作为待用值保留。三个分区可以分别设置不同色调，所有饱和度为 0 时保持 identity。色轮不是 WB，也不替代 HSL 的色域选择。

首批不增加全局第四色轮、亮度轮或局部蒙版；明暗分区和混合权重以技术方案的稳定版本定义，不读取当前图片自动改变区间，以保证参数可复用。复制、预设、历史、Agent 与批量导出包含完整三分区数据。

交互语义参考 [Lightroom 颜色调整说明](https://helpx.adobe.com/lightroom/mobile/adjust-light-and-color/adjust-colors.html)；该参考不代表采用 Adobe 的私有算法或数值映射。

## 9. HSL 取色与目标调整（ITER-07）

- 在混色器提供取色/目标调整入口，选择 Hue/Saturation/Lightness 后在照片上取样并拖动；移动端支持手指取样和可见放大取样提示，桌面支持指针与键盘调整。
- 取样映射到真实照片像素坐标，受 zoom/pan/crop/留白影响时仍准确；不能取到黑边、遮罩、标签或参考示意图。近灰色或不可用像素说明原因，不凭空选择某色域。
- 显示实际受影响的一个或相邻色域。一次手势从冻结的起始 HSL 值与色域权重计算增量，不反复累加到已经更新的值；松开形成一个历史项，取消恢复手势前值。
- 保持八色域三轴的既有核心算法和保存结构，取色只产生相应字段变化，不创建另一套局部调色。离开工具、切图、后台、几何手势或多指缩放时安全取消。
- 三种轴的目标调整均需验收；不把任意点选后固定改某一色域的控件当作取色完成。

交互参考 [Adobe Color Mixer 与目标调整说明](https://helpx.adobe.com/uk/lightroom-classic/desktop/process-and-develop-photos/color-mixer.html)，具体八色域权重沿用 RawLab 现有核心。

## 10. 批量同步与快捷单张微调（ITER-08）

在照片条/缩略图中多选，将当前照片的已提交调整同步到选中照片，复用 ITER-03 的范围、解析、保存、失败与历史事务。来源、目标与数量明确，不能将来源照片误列为待覆盖目标。微调中应用预设以当前照片为目标；来源身份随复制/同步操作冻结。

用户可从该集合进入某张照片独立微调，再返回原选择集合，保留顺序、选择和其他照片编辑；切换前处理草稿与保存失败。单张调整只改该照片。再次同步时预览覆盖范围，未选项保持，支持撤销实际成功目标。返回集合保留本次事务历史入口；预检跳过不取消原集合选择。

区分两种操作并明确命名：

| 操作                     | 是否写目标编辑记录 | 导出内容                                   |
| ------------------------ | ------------------ | ------------------------------------------ |
| 应用调整并保存到所选照片 | 是，逐张报告       | 每张自己的最终设置，可继续单张微调         |
| 仅用于本次批量导出       | 否，保留现有行为   | 现有统一冻结设置；混合输入仍逐张解析相机项 |

逐张模式提交导出时，先对所有目标（包括当前编辑器正打开的照片）预检草稿；应用且保存成功后使用新提交值，放弃使用原提交值，跳过保留草稿并排除本次任务。处理完毕回到确认页显示实际数量与最终调整，再确认冻结每个目标的编辑快照、外观引用、输出设置、稳定身份与顺序；之后编辑不能改变已启动任务。任务取消/恢复/失败重试保留逐张差异，不重复输出成功项。旧版本的统一快照任务仍可恢复，不把它转换成“读目标当前编辑记录”的新行为。

## 11. 多点平滑曲线（ITER-09）

首批提供全局 RGB 主曲线，含端点与可增删/移动的中间控制点；不强制加入独立 R/G/B 通道曲线。x 严格有序，曲线连续平滑，拖动不能交换点顺序；精确坐标、当前点删除、整曲线重置和 identity 线明确。

旧 S 曲线作为独立 legacy 模式保留，加载旧照片/配方/任务必须走原公式。用户切到多点模式是显式编辑，提供保留当前效果的转换或明确确认，不能用粗略曲线替换后仍宣称无变化。新曲线数据进入保存、剪贴板、预设、历史、Agent 和逐张快照；只保存控制点和模式，不把屏幕坐标写入参数。

## 12. 清晰度与去朦胧（ITER-10）

建议范围均 `[-100,100]`，默认 0，独立开关语义由值归零表达。

- 清晰度调整中等尺度局部对比：正向增加层次，负向柔化；不是直接调用现有锐化。验证高反差边缘光晕、噪声放大、皮肤和细纹，不能通过明显边缘描边制造“清晰”。
- 去朦胧调整雾感与远景层次：正向减雾，负向增雾；不是全局对比或简单压黑。验证天空/逆光/无雾场景、色偏、暗端、噪声与极值；不承诺恢复源文件没有的细节。
- 两项的空间尺度随照片尺寸采用同一稳定定义；预览代理是近似，最终导出始终用完整源，100% 参考和缩小后的全尺寸输出用于质量比较。CPU 参考、各 GPU 后端与回退行为均要明确。

ITER-05/06/10 的数值合同与固定质量集须按技术方案 8.7 在本轮冻结；当前均未实施、未达算法冻结，不能因有候选公式就标记完成。范围仍包含这些项，不将质量前置转写成后续版本待办。

## 13. 桌面自动更新（ITER-11）

此项与编辑链并行，但属于本次迭代。保留自动检查和手动检查，新增自动下载并安装（默认关闭）；r4 的 Sparkle 风格是交互参考，不代表两个平台必须使用同一安装框架。

- 更新提示与设置分离：提示版本/内嵌发布说明，并提供“跳过此版本 / 稍后提醒 / 安装更新”；长期设置在“设置→软件更新”，包括立即检查。
- 按 OS/架构/渠道选择可信更新包，下载、取消、进度、校验、准备完成、等待任务和失败重试均可定位。校验包括可信发布身份与包完整性，不能只比较 HTTPS 下载成功。
- 打开/关闭更新设置、检查和下载不提交、放弃或清除照片草稿、未保存状态及原工具。返回编辑器可继续处理草稿；只有明确应用/放弃后才更新对应安装阻挡。
- 安装前处理当前草稿、保存照片编辑与可恢复任务；保存失败或导出/批量未结束则等待，不强杀任务。准备完成后明确选择重启安装或下次退出安装；关闭自动安装后不能后台替换。
- 安装/重启/权限/网络/签名失败保留可启动版本和用户数据，提供恢复与官方手动下载。切换版本不覆盖原始照片、编辑记录、外观和用户预设；失败不能显示已更新。校验/安装失败保留所属阶段与恢复入口，关闭后再次打开仍显示失败；旧下载或校验回调不能把失败变成准备安装，只有明确重试并成功校验后才继续。
- 现有未携带 updater 的旧 ZIP 通过发布页手动安装/迁移到可信“种子版”，之后才提供自动升级；提示不能让旧客户端误以为已经具备自举安装。分别验收旧 ZIP→种子版迁移和种子版→后续版本自动更新。
- 首批安装支持矩阵：macOS arm64/x86_64 签名 `.app`；Windows x64 当前用户 Setup 安装版。Windows 裸 ZIP/portable 继续走手动下载，不显示可用的自动安装开关；旧 ZIP 需先手动迁移到 Setup 种子版，保留原用户数据与旧目录。
- 安装支持说明页只读，查看说明不改变自动安装资格。签名、公证、安装形态与更新 feed 是前置交付。技术方案必须给出两端各自路线；未完成可信发行前不开放一个实际不安全的自动安装开关。实际签名、发布和部署按单独授权执行，本轮文档不执行这些动作。
