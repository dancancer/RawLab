# RawLab: 调整记忆与批量导出 UI 方案

日期：2026-10-09。状态：功能范围与 UI 稿已确认，迁移到 `development` 后的四端验证见[验收记录](../../verification-edit-memory-batch-export-2026-10-10.md)。本目录保留设计稿，不将设计图作为运行截图。

[打开设计板](index.html)。六张图由内置 image_gen 基于现有界面生成；照片、文件名、拍摄信息、参数和任务结果均为示意数据，不是运行截图。原始提示词与修改记录见 [prompts.json](prompts.json)。图中文字、图标和具体比例不能替代下述交互规则；落地使用原生可访问控件，不将图片作为应用界面。

## 已确认范围

- 覆盖 Mac、Windows、Android、iOS；调整记录仅在本机保存，不创建随 RAW 携带的 sidecar，不做云同步。
- 每张照片独立自动保存、恢复。未编辑照片使用客户端默认值，不继承上一张。
- 当前照片的一套设置可以应用到多个 RAW 并批量导出；不叠加目标的已有调整，不覆盖其本机编辑记录。
- iOS RAW 白平衡对齐其他三端；Android 补齐高光、阴影、对比度、S 曲线、饱和度和锐化，参数约定对齐桌面。
- 不重做全局视觉体系，不引入照片目录数据库、预设市场或跨端迁移；不顺带删除 iOS 现有额外工具。

## 视觉与布局

沿用 PRODUCT.md、DESIGN.md 中的照片主导、深灰中性色、黄色功能强调、系统字体和原生工具控件。桌面保留现有左侧文件树与底部调整区，新增独立批量任务窗口，不把导出设置放进主编辑器右侧。手机使用导航页，避免多层弹窗。

桌面任务窗口建议初始 1040x720，最小 900x620。主体左侧约 62% 为目标列表，右侧为设置摘要；两列内容独立滚动，底部操作栏固定。更长的文件名中间省略并提供完整名称提示；同名文件显示来源目录作区分。

移动端以 390pt / 412dp 竖屏为设计基准，320pt 窄屏、横屏和大字号使用可滚动内容，不压缩按钮文字。iOS 点击区域至少 44pt，Android 至少 48dp。不要把 PNG 中的绝对像素直接当成点或 dp。

## 编辑与保存

桌面保存状态放在状态栏；手机放在调整区标题旁。只有落盘成功才显示“调整已保存”，短暂显示后淡出。恢复时显示“已恢复上次调整”。持续调节时不反复闪动、弹 toast 或遮挡照片。

保存失败持续显示错误图标与“调整未保存”，点击可重试；保留当前内存设置。切换照片和正常关闭前完成待保存记录，不能仅在切换后才尝试保存。重置产生的新设置也必须持久化。

记录包含参数值、模式、外观身份和强度，不包括缩放、平移、直方图显示等窗口状态。相同文件名不等于同一照片，临时导入路径不能当作持久身份。首版恢复目标是再次选择同一原始文件或相册资源；不承诺自动追踪所有移动、复制后的副本。

外观丢失时保留原始记录，提示重新定位或选择，不静默回退另一外观。修复前不可使用不完整的设置发起批量导出。

## 参数对齐

Android 工具顺序：胶片、强度、曝光、高光、阴影、对比度、S 曲线、饱和度、色温、色调、锐化。工具是同级横向可滚动项，不新增胶片模式页。选中工具后仅显示该项的数值输入、滑杆和重置。

| 参数 | 桌面基准 |
| --- | --- |
| 胶片强度 | 0-200%，默认 100% |
| 曝光 | -4 至 +4 EV，步进 0.05 EV |
| 色温 | 2000-50000 K，倒数 Kelvin 滑杆，数值输入为 Kelvin |
| 色调 | -150 至 +150 |
| 高光、阴影、对比度、S 曲线、饱和度 | -100% 至 +100%，默认 0 |
| 锐化 | 0-200%，默认 0 |

有符号值的进度表达从默认点到当前值。高光 +25% 的滑杆不能把当前滑块右侧涂黄；工具环从默认值表达正负方向。具体 native 请求转换也要对齐桌面，而不是只复制标签和数值范围。

iOS RAW 白平衡增加“拍摄时 / 自定义”分段控件。默认读取当前 RAW 的相机白平衡；首次手动编辑色温或色调后切换自定义；选择“拍摄时”恢复当前照片基准。色温和色调共享一个模式。缺少有效相机校准时保留相机模式，说明原因并禁用不能可靠使用的手动数值控件，不显示伪造的拍摄色温。普通图片继续走独立处理路径。

批量时，拍摄时白平衡逐张解析，自定义白平衡使用固定数值；曝光基准复制模式，每张照片重新计算其实际基准，不复制来源照片的基准计算结果。不把目标照片的旧参数叠加进本次设置。

## 批量流程

1. 当前照片精确预览可用后，从导出菜单进入“使用当前调整批量导出…”。菜单保留已有单张导出入口。
2. 冻结当前来源照片、参数和外观作为任务草稿。取消草稿不改变原编辑。目标列表初始为空，即使来源照片也出现在候选中，也不能默认勾选。
3. 选择 RAW。桌面使用多选文件选择器；Android 在现有相册中进入选择状态，并可从文件选择；iOS 使用系统照片选择器。重复资源去重，不按同名直接合并。选择后验证是否能取得 RAW，不把普通 JPEG 当作 RAW 悄悄加入。
4. 确认来源、目标、全部调整和输出。零选中时禁用下一步或导出。源设置始终不因浏览目标而改变。
5. 启动后进入任务页；同一时间只执行一个批次，编辑器调整与第二个批次入口暂时禁用。任务信息和取消操作保持可用。
6. 成功、失败和未处理分别统计。重试复用原任务快照，不读取编辑器之后修改的设置，不重新生成已经成功的照片。

选片缩略图仅表示原始候选，不冒充已经应用效果的预览。确认页点击目标缩略图，进入单张效果检查；只对被检查的目标生成效果预览。返回不丢选择，不提交逐张调整。

## 各端确认页

| 客户端 | 目标与输出 |
| --- | --- |
| Mac / Windows | 左侧目标列表，右侧固定来源与参数、JPEG / 16-bit PNG、文件夹选择。原始分辨率、重名自动加序号只读。 |
| Android | 来源摘要、目标缩略图、输出依次纵向排列。JPEG / 16-bit PNG；系统支持相册保存时可选相册，另提供一次选择输出目录。不得逐张弹 CreateDocument。 |
| iOS | 同样的信息顺序；首版固定 JPEG、原始分辨率、照片图库，三个值均无下拉箭头。 |

“全部调整”只读展开，避免在确认页维护第二套可编辑控件。“更改”仅返回目标选择。主操作显示实际数量“导出 N 张”。底部注明“仅用于本次导出，保留各照片原有调整”。

桌面目标行有勾选与移除两个动作：取消勾选暂不参与，移除从草稿列表去掉。Android 选片保留已有网格列数和比例偏好；图稿三列只是示例。“全选”仅选择当前列表，跨相册已选项继续保留。

## 任务状态

| 状态 | 信息 | 操作 |
| --- | --- | --- |
| 准备中 | 检查目标可读性和输出权限 | 取消；重新授权或选择位置 |
| 导出中 | 已完成 N / 总数、当前文件；各行等待/处理/成功/失败 | 取消导出 |
| 正在停止 | 正在停止，不虚报已取消 | 等待当前不可中断阶段结束 |
| 全部成功 | 成功数量、输出位置 | 打开文件夹或完成 |
| 部分失败 | 成功、失败数量及逐文件原因 | 重试失败项、打开已完成结果、关闭 |
| 已取消 | 成功、失败、未处理数量 | 继续未处理项、关闭 |
| 已中断 | 保留任务记录，不暗示后台仍在运行 | 重新授权后继续未完成项、放弃任务 |

个别输入失败不阻断其他照片；磁盘空间不足等全局错误停止批次。正在生成的临时文件不显示为成功，失败或取消后清理。成功以实际输出保存完成为准，不能以渲染结束代替写入照片图库完成。

重名自动加序号，不覆盖旧输出，不改写 RAW。每张输出保留该目标自己的可读取拍摄元数据，不能把来源照片的 EXIF 复制给整批。移动端按前台执行设计，不承诺退出后持续显影；恢复和重试需要避免重复生成已完成结果。

## UI 验收要点

- 来源、目标、数量和作用范围无需打开帮助即可辨认；缩略图和文件名对应稳定。
- 单张/批量使用同一参数约定；拍摄时模式不能变成复制来源照片的色温。
- 关闭重开恢复同一照片设置，重置后不复活旧设置，同名照片不串记录。
- 大字号、长文件名、零选中、1 张、多屏列表、权限失效、全部失败均有可达状态。
- 保存状态、任务状态、焦点和选择不能仅靠颜色表达；屏幕阅读器能获取数量、文件名和进度变化。
- 图稿批准不等于原生运行验证通过。实现后另做四端原生截图、操作与导出结果验证。
