编辑并自动保存 → 使用当前调整批量导出 → 选择 RAW → 确认 → 处理与结果

四端遵循同一套任务规则，使用各自原生交互。当前照片是固定的调整来源；批量任务只生成新成片，不覆盖目标照片的调整记录。

Mac · 一页完成导出确认

左侧核对目标，右侧核对来源和输出；不改变现有主编辑器布局。

固定来源

进入流程时冻结照片、外观和参数。左侧勾选目标不改变右侧来源。

目标列表

加号继续选文件；勾选参与本次任务；移除只影响本次列表。点击缩略图检查应用后的预览。

明确输出

JPEG / 16-bit PNG、输出目录可选。尺寸固定为原始分辨率；重名自动添加序号，这两项为只读值。

开始前

显示实际数量。零选中时禁用导出；不可用项目标明原因，可移除后继续。

Windows · 完成不掩盖失败

Mac 共用这一结果结构，保留各自的窗口和控件样式。

处理中

同一区域显示“已完成 3 / 6”、当前文件和进度。底部主操作替换为“取消导出”。

部分失败

数量与列表一致；“重试失败的 1 张”沿用原任务的设置，不读取编辑器后来修改的值。

全成功

隐藏重试，突出“打开文件夹”。照片图库输出则显示“完成”，不冒充文件夹。

取消

先显示“正在停止…”，结束后分别列出成功、失败、未处理；已完成的文件保留。

移动编辑器 · 记忆调整与参数对齐

照片仍占主要空间；保存反馈不覆盖画面，也不增加保存按钮。

移动批量流程 · 先选照片，再确认导出

Android 使用现有相册选择模式，iOS 使用系统照片选择器。以下分别展示选片和确认两个关键节点。

状态与边界

状态界面反馈与操作
自动保存保存成功才显示“调整已保存”；快速连续调节时不反复闪动。重新打开显示“已恢复上次调整”，随后退回安静状态。
保存失败持续显示带错误图标的“调整未保存”，提供重试。保留当前数值，不伪装成已完成。
外观丢失保留设置，提示定位或重新选择外观；修复前不能以另一外观静默导出。
空选与读取失败0 张时禁用下一步/导出。选后验证 RAW 可用性，不支持或不能读取的文件逐项解释，允许移除。
权限与空间开始前检查保存权限。目录授权失效可重新选择；空间不足停止任务，保留已完成结果。
中断与恢复前台批处理；保留任务记录。返回时显示“导出已中断”，用户选择继续未完成项，缺少照片访问权限时重新授权。
窄屏与大字号正文和文件名可换行，数值不挤压标签。手机主要操作固定在安全区上方；横屏/大字号内容滚动，不把全部工具强塞进屏幕。
