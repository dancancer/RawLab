# ITER-03：Windows 接入

沿用 [payload v1](../../design/editing-iteration/selective-payload.md)、原有 WPF/native request
和 `EditStore` 格式。主代理负责实现；默认代理只读核验。目标为现有 draft PR #134，
不包含合入、发布或 AI 交换格式扩展。

- [x] C# 字段合同及 adapter 消费共享向量；保留目标 processing、相机校准和未选值。
  使用实际 Float request 验证配方反算；不经过 UI setter 或添加 clamp。
- [x] Registry v1 增加可选 revision/tombstone；加锁、重新读取、完整前态 CAS 和原子写入。
  旧文件只读不迁移。会话保存逐照片历史顺序，支持部分失败重试与独立 redo 失效。
- [x] 普通离散编辑、拖动、几何 Apply 和复制粘贴统一提交；取消和过期回调不保存。
  文本输入保留自身 undo。复制范围、逐目标预检/结果和会话历史提供原生 WPF 入口。
- [x] 先执行纯模型回归，再在独立 Windows 工作目录构建当前源码的 core/WPF，运行真实
  原生入口及受影响的编辑、几何、保存恢复回归。重定向应用记录、用户配置和批量日志，
  检查默认配置文件的内容与修改时间保持不变。
- [x] 独立只读复核、六语资源生成和 CI 契约检查。交付沿用原 draft PR，远端源与 CI
  的实际结果留在 PR，不把本地原生通过当作 Hosted CI 通过。

AI 开关仅进入完整本端历史。来源 AI 的 all/modified、目标 AI 的普通降噪选择按共享
合同阻挡。Windows 不支持非零 FBDD/post-RGB 请求；不得伪装成功。启用镜头校正需
读取目标原生匹配结果。`recipe-lut:<id>` 只解析 LUT，不重新套用配方参数。

批量结果页直接操作本次事务的成功分量，并显示可撤销/重做数量。撤销成功项后继续
重试失败项，不重写或重新接管已撤销的照片。结果行从同一事务状态区分保存与撤销；
嵌套历史恢复若需要重新载入，关闭父结果页后再读取最新记录。编辑菜单的重置部分
只重建自己持有的动态项，保留复制、粘贴与历史入口。

原生验证采用现有 `build-remote.py`、`run-v08.ps1` 和交互桌面测试入口；纯模型通过或
WPF 编译通过不能替代实际 UI 执行。机器、源码哈希、命令和测量结果记录在 PR。
