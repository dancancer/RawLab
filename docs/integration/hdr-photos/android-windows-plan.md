# Android / Windows HDR 实施计划

设计依据：[平台对齐设计](../../design/hdr-photos/android-windows.md)。
本计划是现有 Apple 首批交付的后续阶段，不改变其尚未完成的物理设备验收门槛。

| 阶段 | 内容 | 接口边界 | 完成条件 |
| --- | --- | --- | --- |
| P1 共享文件层 | 跨平台 gain-map 探测、双图解码、内存准入、原子导出、固定依赖与许可证 | 现有 `sony2fuji_hdr.h`；Apple 默认适配器不变 | 真实 JPEG / HEIC 与合成损坏输入回归；MSVC / NDK 可编译 |
| P2 Android | JNI pair 生命周期、HDR 设置和持久化、编辑 / 显示 / 监控、预设 / 同步 / 批量 / 导出 / LUT 向导 | `RawLabAndroid/` 内适配，使用共享 HDR C ABI | JVM、native、构建、模拟器界面和导出回读 |
| P3 Windows | P/Invoke pair 生命周期、HDR 快照、编辑 / 显示 / 监控、预设 / 同步 / 批量 / 导出 / LUT 向导 | `RawLabWindows/` 内适配，使用共享 HDR C ABI | 模型测试、原生构建、可用桌面界面和导出回读 |
| P4 集成 | CLI 能力、跨平台传递、资源释放、性能与回退检查 | 共享协议和各端现有发布事务 | 整体复评；记录已验证平台与硬件缺口 |

共享文件层由主线程维护；Android 与 Windows 可在上述稳定 ABI 上独立接入。
先补失败的行为回归，再实施最小充分改动。最终验证必须使用实际源码构建，
界面编译成功不能记作界面测试通过。单次执行日志、测量和截图保留在临时目录或 PR，
不入库。提交只包含本次源码、必要测试与长期文档，不包含原片和生成产物。
