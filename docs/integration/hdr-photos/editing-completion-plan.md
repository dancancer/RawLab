# HDR 编辑功能补齐计划

> 按批次交付。每批先固定数值与存储契约，再实现并验证各客户端、全尺寸导出和适用的调整传递。执行顺序与验收记录遵循 [集成协作规范](../../process/integration-workflow.md) 和 [验证 SOP](../../process/ci.md)。

基线为 `origin/development@48b8707f568fc04219d60ad4f9d4eea0a2b3631a`。目标是让现有 HDR 编辑来源逐步获得可保留高光层次的编辑工具。按批次确定发布版本和 PR。主代理负责共享 C++、C ABI、数值契约和联合验收，各平台接入以同一接口和版本为准。

现有 [HDR 颜色契约](../../../lutools/docs/hdr-color-contract.md) 以浮点 `1.0` 为 SDR 参考白。HDR 主图和 SDR 底图使用同一份编辑状态，分别计算颜色，统一执行几何和缩放。现有 v1 记录和增益图往返是回归基线。新增算子以中性值精确旁路，已有记录重开应复现原像素，未知版本或不兼容字段在写入前拒绝。预览与全尺寸导出采用同一数值合同，ProRAW 分块导出也纳入验收。

## 顺序与验收

| 批次 | 交付 | 依赖与关闭条件 |
| --- | --- | --- |
| 1. 自动曝光 | 在四端现有曝光入口新增 HDR 测光，结果写回当前 HDR 曝光值 | 沿用 v1 记录。浮点主图测光、界面提交、撤销、重开和导出均已验收，移动端使用模拟器 |
| 2. 黑白场和曲线 | HDR 黑场、白场、S 曲线及自定义曲线 | 扩展共享 HDR 请求、持久化、传递和 Agent。亮度曲线以参考白为标尺，亮部按曝光档延伸。灰阶单调、跨参考白连续、零调整精确旁路，验证 HDR/SDR 预览与增益图往返 |
| 3. 颜色 | 鲜艳度、八色域 HSL 和画布取色、三分区颜色分级 | 在第 2 批的请求和记录基础上增加处理版本 3。覆盖灰轴、肤色、宽色域与超白，取色使用处理阶段的浮点样本。验证缩放、裁剪、对比和触屏手势 |
| 4. 双图呈现与调整传递 | HDR 输出亮度上限、独立 SDR 底图调整、普通相机 RAW HDR 的基础预设／复制／同步和逐目标批量，补齐集合输出入口 | 区分内容峰值与屏幕容量。只修改 SDR 底图时 HDR 主图保持相同，增益图从两份新输出重建。目标来源逐张预检，区分统一参数与各自保存调整 |
| 5. 效果和细节 | 暗角、颗粒，再接锐化、清晰度、去朦胧和图像级降噪 | 暗角与颗粒以全图坐标计算。邻域算子建立跨块输入规则，去朦胧等全局分析与整图基准一致。用全尺寸原片核对接缝、纹理、延迟、峰值内存及取消 |
| 6. 外观 | HDR 胶片外观、明确声明 HDR 输入输出的 LUT、HDR 大师配方、经验证的 RAW DCP／RLOOK | 依赖已交付的调色工具。HDR LUT 固定色域、场景／显示参考、传递函数、参考白、覆盖范围和越界策略。每个外观先验收高光与中性灰，并分别验证 HDR 主图和 SDR 底图。旧 SDR 外观仍按其原合同解析 |
| 7. 相机显影 | 相机空间白平衡、曝光基准、镜头畸变与色差、适用 Bayer RAW 的 FBDD，随后评估并接入通过验收的 GPU AI 降噪 | 修改源解码选项与缓存身份。Bayer 算子要求真实传感器输入，线性 ProRAW 与手机照片走各自的来源能力。AI 用支持的平台硬件 GPU 验证效果、源身份和失败恢复，保留现有 CPU 处理策略 |
| 8. HDR 输出格式 | 在增益图 JPEG 之外增加经过验证的 HDR 输出，优先评估 HEIF | 用真实写入和外部读回选择编码路线。覆盖色域、位深、传递函数、元数据、HDR／SDR 查看器兼容和失败原子性，单独记录各端能力 |

## 批次 1 的实施步骤

- [x] 在 `lutools/tests/hdr_api_tests.cpp` 添加 `autoExposure` 回归。线性灰 `0.09225` 得到 `+1 EV`，`0.369` 得到 `-1 EV`，中灰不变。暗图含占比超过 0.5% 的 `8.0` 高光时不再额外增曝。无测光信号、非法白平衡和无效输入不修改输出值。
- [x] 在 `sony2fuji_hdr.h` 和 `sony2fuji_hdr.cpp` 增加 `sony2fuji_hdr_estimate_auto_exposure(const sony2fuji_hdr_image_pair_v1*, float temperature, float tint, float* exposure_ev, sony2fuji_hdr_diagnostic_v1*)`。用有界 PREVIEW 原始 HDR 主图与当前相对白平衡测光，不读取屏幕容量或当前曝光值。复用原有测光采样和 `[-4,4] EV` 边界。中位数目标为 `0.1845`，增曝受第 99.5 百分位和 `4.0` 参考上限约束，已有较亮高光时增曝上限为零。
- [x] Apple 通过 `Shared/Native/HDRImage.swift` 共享测光接入。Mac 的 `RenderEngine.autoExposure`、iOS 的 `Sony2FujiProcessor.autoExposure` 都复用有界 HDR 来源。原有操作完成后检查照片、模式和编辑版本，通过正常曝光设置入口提交一次历史记录。
- [x] Android 从 `EditorRenderer` 复用 HDR 来源缓存和 `NativeHDRBridge`，通过 JNI 调同一 C API。Windows 从 `RenderEngine.AutoExposure` 复用 `HDRSourceCache`，通过 `HDRNative` 调同一接口。用已有曝光动作提交 HDR 字段并保留独立 SDR 快照；强制 GPU 模式不可运行 CPU 测光。
- [x] 验证 `hdr_api_validation` 与既有 HDR、SDR 和导出回归；通过 iOS 和 Android 模拟器的自动曝光、撤销／重做测试，核对可用的 HDR 导出路径。macOS 跑实际编辑模型回归，Windows 跑 HDR 模型检查和目标编译。
- [x] 通过 macOS 实际编辑窗口的自动曝光、重复测光、撤销／重做、切图和重开。界面导出 HDR JPEG 后读回 ISO/XMP 增益图。
- [x] 在 Windows 实际桌面运行 WPF 原生回归，核对测光、撤销／重做、重开和导出，并验证强制 GPU 时的拒绝行为。结果按 [验证 SOP](../../process/ci.md) 留存。

## 批次 2 的实施步骤

- [x] 为 HDR 浮点亮度定义黑白场和曲线。以 `s = log2(Y)` 为档位，黑场权重在 `[-7,-3] EV` 平滑降至 0，白场权重在 `[-1,+3] EV` 平滑升至 1，各自范围 `[-100,100]` 对应最大 `±2 EV` 偏移。两个区间分开，灰阶扫过 `2^-8…2^8` 时验证新增算子单调。随后把 `[-8,+8] EV` 映射到曲线的 `[0,1]`，参考白在 0.5，端点固定，曲线区间外维持原档位。复用单调插值和亮度比例缩放 RGB，验证 HDR 主图与 SDR 底图的暗部、参考白和超白。
- [x] 扩展 `lutools/src/core/hdr_rendering.cpp`、`sony2fuji_hdr.h` 和 `sony2fuji_hdr.cpp`。采用独立的处理版本与有长度检查的扩展请求，保留 88 字节 v1 前缀及旧调用语义。渲染、通用分块导出和 ProRAW 导出共用请求解析和色彩算子。用同一测试向量比对整图和分块，并验证过短配置、错误版本、NaN 和非单调控制点的失败路径。
- [x] 在共享 Swift、Android 和 Windows HDR 记录中保存黑白场、曲线模式与控制点，接入版本化传递和 Agent。旧记录读取为中性并保持原版本，第一次提交新算子时才升级。验证旧记录重开、保存新曲线、复制到兼容 HDR、拒绝不兼容目标和原有批量快照。Agent 保持 HDR schema 6 可用，通过能力协商使用 schema 8。
- [x] 四端已在现有明暗与曲线工具中开放 HDR 入口。Windows 桌面、iOS 和 Android 模拟器通过曲线拖动、撤销、重开及 HDR／SDR 切换。macOS 隔离窗口通过黑白场、点曲线浮点输入、撤销／重做及切图重开。

## 批次 3 的实施步骤

- [x] 为扩展线性 RGB 建立鲜艳度、八色域 HSL 和三分区分级。鲜艳度按相对色度控制增益并保护肤色。HSL 复用色相分区，单独计算 HDR 色度和明度。分级按参考白上下的曝光档位过渡。原生测试覆盖中性精确旁路、跨档位连续性、灰轴、超白和负通道。
- [x] 增加处理版本 3 请求和记录。以 v2 请求为前缀，单独校验颜色尾部。预览、整图和 ProRAW 分块使用同一颜色阶段。旧版记录和配方按原处理版本执行。
- [x] 增加 HDR 取色入口。以应用几何后的浮点主图为采样对象，取样阶段在鲜艳度之后、八色域 HSL 和分级之前。已接入四端的坐标换算和编辑代际，原生检查覆盖裁剪、旋转、缩放和旧请求失效。
- [x] 四端颜色工具已接入当前 HDR 记录、调整传递、批量和 Agent schema 9。iOS 和 Android 模拟器、Windows 桌面通过编辑流程。macOS 通过原生取色渲染，并在隔离窗口实测鲜艳度、画布取色拖动、高光分级和 HDR 调整复制粘贴。

## 批次 4 的实施步骤

- [x] 在共享渲染增加处理版本 4。HDR 主图以 SDR 参考白为标尺设置内容亮度上限，0 表示不限，其他值以参考白以上的 EV 表示。在上限以下建立平滑高光压缩，保留颜色比例。SDR 底图在共同调整后独立应用曝光、对比度和饱和度。已验证两份浮点输出互不影响、中性 v4 与 v3 逐位一致、分块和整图对齐。
- [x] HDR 输出亮度上限和 SDR 底图调整已接入四端编辑、持久化、传递和 Agent。Windows 桌面与 iOS、Android 模拟器通过历史、重开及 HDR／SDR 隔离检查。macOS 隔离窗口实测上限、兼容预览切换、底图参数独立调整及重开恢复。
- [x] 按来源能力开放普通相机 RAW HDR 的复制、预设和同步。准备阶段逐个核对目标身份、保存的编辑模式、显影版本和格式。相对白平衡及 HDR 专属工具的值仅在兼容 HDR 目标间传递，批量来源为相机 RAW 时仍保持目标原来的模式。
- [x] 补齐集合输出入口。Windows 实际桌面已通过普通 DNG 和 ProRAW 的逐目标批量。iOS 模拟器已在同一集合预检普通 DNG、ProRAW、增益图和普通 SDR，并冻结各自调整。macOS 已验证 48MP ProRAW 流式批量及两种 JPEG 读回，Android 已覆盖对应模型和普通 RAW 两种输出。

## 批次 6 的实施步骤

- [x] 显式 HDR CUBE 已接入共享原生渲染。输入和输出使用显示参考的扩展线性 sRGB，参考白为 1.0。查表在声明的域内插值，越界分量按原输入与域边界的差值延伸。原生测试通过中性、超白、宽色域负通道、旧格式拒绝、整图与流式一致和资源替换拒绝。
- [x] 处理版本 7 已保存外观资源指纹和强度，接入四端的编辑、传递和逐目标批量。CLI schema 13 与 Windows 桌面通过导入、重开和增益图读回。iOS、Android 模拟器和 macOS 隔离窗口通过系统文件选择、强度、清除及撤销。
- [x] 四端已接入原创的 HDR Silver 黑白外观和 HDR Silver Master 配方。原生检查覆盖负通道、参考白、超白、中性轴和通道权重。Windows 桌面与 iOS、Android 模拟器通过配方应用。macOS 隔离窗口通过应用、复制粘贴、重开及黑白场与曲线数值检查。
- [x] 共享核心已接入匹配机型的固定 D65 线性校准。原生接口读取 DCP 或矩阵型 RLOOKHDR，以资源 SHA-256 固定解码输入。合成 Bayer DNG 和 Sony ILCE-7CM2 原片通过两种资源的双图像素一致性、灰轴、负通道和超白回归。矩阵和显示外观分别按各自的颜色合同解析。参考 [HDR 颜色契约](../../../lutools/docs/hdr-color-contract.md) 和 [DNG 1.7.1.0 规范](https://helpx.adobe.com/content/dam/help/en/photoshop/pdf/DNG_Spec_1_7_1_0.pdf)。
- [x] 用 [Image Engineering 的 D65 模拟光源样片](https://www.image-engineering.de/en/products/measurement-devices/camspecs) 验收固定 D65 线性校准。Panasonic DMC-ZS100 的色卡原片保留 Bayer 采样转为 DNG。测试 DCP 使用同机型 Adobe Standard 的 D65 ColorMatrix 反推线性 ForwardMatrix，只用中灰设定白平衡和曝光。对照 [BabelColor 独立测量](https://babelcolor.com/colorchecker-2.htm)，24 色块 ΔE00 中位数 1.54、P95 3.35，六阶灰最大 1.44，白块亮度为参考白的 2.20 倍。原片和测试配置仅用于本地验收。
- [x] 四端在 HDR RAW 设置中导入和清除固定 D65 的 DCP／RLOOKHDR。配置随照片保存并在重开时恢复，逐张批量读取目标照片自己的配置，缺失时提示重新导入。macOS 和 Windows 启用相机配置时使用线性校准显影并关闭 HDR AI 降噪。
- [x] 完成 HueSatMap 评估。Adobe Standard 只取 ForwardMatrix 时，D65 色卡的色块明显偏淡。现有 SDR 查表会将分量限制在 0 到 1。后续可以增加独立的 HDR HueSatMap 阶段，先定义参考白两侧及负通道的查表行为，再用色卡、灰阶和超白验收。当前交付范围为固定 D65 线性矩阵。
