# RawLab v0.9.1

Version `0.9.1`, build `16`. This release brings phone HDR photo editing to
supported Apple platforms, explicit LUT color compatibility, refined master
recipes and more compact editing controls. It includes the changes merged after
[v0.9.0](https://github.com/dancancer/RawLab/releases/tag/v0.9.0).

## Changes

- **Phone HDR photos on Mac and iOS.** Import supported iPhone gain-map HEIC/JPEG
  and Android Ultra HDR JPEG files, adjust exposure, relative white balance,
  contrast, highlights, shadows and saturation, and apply geometry adjustments.
  Inspect HDR and SDR presentations, HDR histograms and false color, then export
  a new gain-map JPEG or an SDR result. HDR JPEG export regenerates the gain map
  from the edited result.
- **LUT compatibility setup.** CUBE/VLT import can use explicit input/output
  color spaces, ranges, interpolation and base rendering. When this information
  or its source evidence is missing, a compatibility dialog lets the user
  configure supported choices and preview the result before importing. Cancel
  leaves the selected look unchanged. Compatibility choices remain unverified
  appearance assumptions; they do not certify a camera or author match.
- **Refined master recipes.** Recipe version 4 uses black/white point, vibrance,
  tone curves and color grading in addition to the previous controls. Recipe
  strength consistently covers those fields, including saved manual edits,
  presets, selective copy/paste, batch export and Agent output. Existing edits
  retain their stored recipe behavior; applying a recipe again opts into its
  updated defaults.
- **More compact editing controls.** Desktop tools use two navigation rows;
  mobile controls leave more room for the photo and adapt to landscape and
  larger text. Crop position and size use precise numeric controls with up to
  two decimal places, together with aspect-ratio locking and orientation swap.
  Slider and ruler layouts remain stable as values change.
- **Reliability fixes.** Windows AI models load from paths containing Chinese
  and other Unicode characters. Android cancels obsolete preview work and keeps
  literal percentage signs in generated copy. LUT percentage lookup and Apple
  localization coverage are corrected. HDR sources can be inspected in the LUT
  compatibility preview, and iOS status dismissal and Photos workflows are
  improved.

## Compatibility

- HDR editing/export requires **macOS 15+** or **iOS/iPadOS 18+**. macOS 14 retains
  existing SDR support and explicitly refuses unsupported HDR editing records.
  Windows and Android clients do not gain HDR editing/display in this release.
- An HDR-capable display is needed to see extended brightness. An SDR display
  can still edit and export supported HDR files, with an SDR-compatible view.
- This HDR scope covers supported static gain-map photos. RAW HDR development,
  exposure merging, native PQ/HLG files and HDR HEIF export are not included.
  LUTs, DCP profiles, look-based recipes, curves, HSL, color grading and detail/AI
  effects are not applied in HDR editing mode in this first implementation.
- New explicit LUT color contracts use the shared CPU photo renderer. GPU Auto
  falls back to CPU for these contracts; Force rejects unsupported execution.
  Existing legacy LUT GPU behavior remains unchanged.
- Recipe strength above 100% retains existing LUT extrapolation and may amplify
  color reversals. Recipe refinements do not change that behavior.
- The desktop update, signing, GPU-only AI, model-license and downgrade limits
  from [0.9.0](v0.9.0.md#upgrade-and-compatibility) continue to apply. Windows
  automatic updates require a current-user Setup installation. Desktop automatic
  checks are enabled by default; automatic download and installation on quit
  require the user to enable that option. The ZIP remains
  a manual-install option. iOS distribution requires valid signing/provisioning.

platform/device coverage limits. Compilation is not device or UI acceptance.
