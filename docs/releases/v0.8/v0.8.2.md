# RawLab v0.8.2

Version `0.8.2`, build `14`. Release preparation based on `development` at
`889e93bd8e6eedf660ef6838c168157ae51db2f7`, compared with the published `v0.8.1`
tag. This release adds direct DCP import, expands RAW compatibility and improves
editing and export responsiveness.

## Changes

- **DCP import on every client.** macOS, iOS, Android and Windows can import
  supported `.dcp` color profiles directly into the custom-look library.
- **More RAW formats.** Add Nikon HE/HE* NEF and Sony ARW6 / Compressed RAW 2
  decoding, enable Sigma X3F input and JPEG-compressed DNG decoding, and update
  recognition for Sony A7 V/A1 II, Canon R50 V and PowerShot V1.
- **Faster editing.** Optimize CPU look processing and geometry rendering.
  Interactive crop, rotation and perspective previews use the viewport size;
  final exports retain the full-resolution processing path.
- **Windows image import.** Accept valid JPEGs with both ICC and EXIF color
  metadata, correct the colors of scaled first previews, and align
  white-balance rounding with the other clients.
- **iOS ordinary images.** Speed up preview initialization and single-image
  JPEG/DNG exports, reducing repeated decoding and peak memory. Keep imported
  sources available during asynchronous import, editing and frozen batch exports.
- **Android batch reliability.** Improve progress and restart recovery, handle
  checkpoint failures explicitly, and reduce journal work for larger jobs.
- **Interface polish.** Complete remaining cross-platform wording, translation
  fixes, error messages and accessibility labels.

## Compatibility

- DCP import accepts a supported subset, including an embedded tone curve and
  explicit supported black-render policy. It does not promise complete Adobe
  rendering or identical camera colors. See the
  [DCP import contract](../../../lutools/docs/lut-preparation.md#dcp-appearance-adaptation).
- Nikon HE/HE* sample coverage includes Z f, Z50 II and Z6 III. Other cameras
  and compression variants need their own verification. Sony and other RAW
  samples establish decoding compatibility, not camera color calibration.
  See [RAW format support](../../reference/raw-format-support.md).
- Platform requirements remain Windows 10/11 x64, macOS 14+, Android 8+ and
  iOS 18+. iOS distribution still requires valid signing and provisioning.
- Usage-statistics behavior and the applicable
  [0.8.1 limits](v0.8.1.md#boundaries-and-known-limits) remain in effect.

## Release Status

This is an unpublished release draft. The six CI checks for the development
base passed in [run 39357644114](https://github.com/dancancer/RawLab/actions/runs/39357644114).
That result covers the base commit, not the version changes or final packages.
Candidate packages are prepared locally; their source identities, checksums,
executed checks and signing state belong in the delivery manifest. Local build
and package checks do not replace physical-device acceptance. There is no
`v0.8.2` tag or published package yet.

Release packaging also corrects the embedded iOS statistics framework's invalid
minimum-system metadata to match its binary. The vendor binary and shared SDK
cache remain unchanged.

The processing core and patched LibRaw have changed since 0.8.1. Rebuild native
dependencies and all intended clients from the frozen release source; do not
reuse the 0.8.1 native binaries. Use the existing
[macOS](../../../RawLabMac/README.md),
[Windows](../../../RawLabWindows/README.md),
[Android](../../../RawLabAndroid/README.md) and
[iOS](../../../lutools/platform/ios/README.md) build instructions. Published
asset identities, checksums and build provenance must come from those actual
release builds.

The concise Chinese announcement is in
[the Xiaohongshu draft](v0.8.2-xiaohongshu.md).
