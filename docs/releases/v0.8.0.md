# RawLab v0.8.0

Version `0.8.0`, build `12`. This release extends the existing RAW editor with
desktop automation, geometric editing and ordinary-image input on all clients.
The underlying RAW, film-look, recipe, HSL, denoise and rendered-DNG workflows
remain available; no original photograph is modified.

## Highlights

- Desktop Agent/CLI JSON editing covers the existing core's complete supported
  parameter set, capability discovery, file information, preview and final
  export. GUI, Agent and frozen batches share rendering semantics. This is a
  local interface, not a new server framework or mobile Agent/MCP service.
- Crop, rotate, straighten, flip and perspective correction use the same
  committed geometry for preview and FINAL export. Draft changes, undo/reset
  and batch snapshots remain separate from committed edits.
- Ordinary-image import, editing, native-size export and mixed RAW/image batch
  processing now work on all four clients. JPEG/PNG are shared; macOS/iOS also
  accept TIFF/HEIF and Windows accepts classic single-page TIFF.
- Opening a photo starts with a single preview. Before/after comparison is
  available explicitly rather than being enabled by default.
- White-balance controls use one combined entry, and collapsed vignette controls
  no longer show duplicate resets. The same fixes cover all platform editors.
- Twenty-nine additional built-in creative looks include the independently
  authored Ektar look, camera-inspired looks and film-inspired RGB looks, with
  consistent artwork and grouping. They are creative interpretations, not
  manufacturer-certified matches.
- macOS builds target version 14 on Apple Silicon and Intel. The hosted workflow
  builds both architectures and exercises the existing CPU-safe parity suites;
  exact candidate results are recorded in the release PR and provenance.
- Default builds include SDK-free, opt-in usage statistics controls, without
  bundling or activating the optional private-local vendor RUM SDK.

## Boundaries and Known Limits

- Ordinary input is single-frame opaque RGB8 SDR. HDR/gain maps, transparent,
  high-bit-depth/float, unsupported non-RGB/profiles and animated/multipage files
  are rejected rather than silently flattened. Android supports JPEG/PNG only;
  Windows does not enable HEIF/BigTIFF. See the [input verification](https://github.com/dancancer/RawLab/blob/a38ac6065f747cc43ddbee1c8df232c049b288d2/docs/verification-raster-input-all-platforms-2026-10-16.md).
- Rendered float32 DNG is a baked SDR appearance, not reversible sensor RAW or
  HDR output. Editable multi-point curves, AI denoise/upscaling, HDR export and
  video generation remain outside this release.
- macOS 14 is the deployment minimum; newer-host build/bundle checks do not
  establish an actual macOS 14 physical-runtime pass. Current physical/simulator
  color, memory, GPU and OEM coverage retains its documented limits.
- iOS has no configured distribution signing or provisioning. The unsigned IPA
  is not an App Store/TestFlight or directly installable package. Device signing,
  minimum-OS hardware, memory and thermal acceptance remain separate.
- The owner authorized formal distribution of the 28 adapted third-party LUTs
  with attribution and the unresolved risk record retained. Their redistribution
  permission remains `UNCONFIRMED`; this is not an original-author license grant.
  The project-authored Ektar look is separate. See [the source audit](../luts/README.md)
  and [attribution notice](../../Shared/BundledLooks/NOTICE.md).

The [release checklist](v0.8.0-preparation.md) and package provenance distinguish
actual executed checks from untested hardware or optional distribution channels.
