# RawLab v0.8.1

Version `0.8.1`, build `13`. A follow-up to [v0.8.0](v0.8.0.md) that fixes
interface and translation details on all four clients, turns usage statistics
on by default and removes permissions the Android app did not need. Editing,
rendering and export behavior is unchanged; the shared processing core is the
same source as v0.8.0.

## Changes

- Usage statistics are on by default on all four clients. Release builds now
  include the Alibaba Cloud RUM SDK and report to the production environment;
  data is processed by Alibaba Cloud and stored in mainland China. RawLab
  reports feature-use counts, never photos, previews, file names, paths, EXIF
  or AI content; the vendor SDK may also collect device identifiers, device
  and system information, network/IP address, region and session data. To
  count active devices the app stores a random installation ID on the device;
  it contains no personal information and is deleted when statistics are
  turned off. Turn statistics off in About RawLab (macOS, Windows, Android) or
  More > Privacy settings (iOS).
- The statistics and privacy text is translated into all six interface
  languages.
- Master recipe names written in Chinese characters (Hideaki Hamada, Takashi
  Yasui, Takahiro Sakai) follow the interface language.
- iOS recipe tiles no longer show an extra icon under the artwork, and the
  recipe panel no longer repeats the recipe name. The settings menu has a
  spoken name for VoiceOver.
- Android shows recipe artwork, no longer falls back to Chinese text when a
  screen is created before the app finishes starting, and no longer requests
  phone-state, network-state or installed-app visibility permissions.
- Windows photo-effect controls use complete translation entries instead of
  composed ones.
- Counts read "Photos Selected: 1" or "Export Photos (1)" on every client, so
  a single photo is never called "1 Photos". Batch summaries use the editor's
  setting names and show disabled switches as Off.
- macOS: toolbar toggles show their on state; the system menus follow the
  chosen interface language; recipe card subtitles, German labels and Japanese
  tool names are no longer cut off or broken mid-word; an empty batch window
  explains itself; export formats have the same names in the toolbar and batch
  export; the collapsed vignette row lines up with the other panels.
- iOS: the batch summary lists each setting once with the editor's names;
  value badges and white-balance captions follow the interface number format;
  each tool panel opens from the top; the header reset menu no longer looks
  like the parameter reset button; geometry controls line up; the export title
  is no longer truncated; the custom size field has a VoiceOver name.
- Windows: every tool and menu has its own icon; other languages no longer
  show Chinese recipe names or internal type names; menus open under their
  buttons; reset menus name their groups; the About window's Close button is
  always visible; status text no longer repeats the GPU setting; a failed open
  clears the rendering status.
- Translation fixes in German, French, Spanish and Japanese, and one name
  ("Look") for imported looks on every client.
- Android: the changed-value marker sits below the tool name as on macOS and
  iOS; menu items line up with their icons; Intensity and HSL, and the header
  and row reset buttons, have distinct icons; the noise reduction group reset
  says so.
- Interface copy on every client is generated from one shared source with
  macOS as the reference, so the same text no longer reads differently on
  iOS, Windows and Android.

## Boundaries and Known Limits

- All v0.8.0 [boundaries](v0.8.0.md#boundaries-and-known-limits) still apply.
- The vendor SDKs' redistribution terms are not yet confirmed in writing; the
  owner chose to ship them and the packaged notices say the terms are pending.
  The GPL linking exception grants no rights in the SDKs themselves.
- The macOS SDK bundles libcurl 7.68.0 from the vendor; it cannot be updated
  independently of the vendor SDK.
- The Android SDK has no x86_64 native core. On x86_64 devices statistics show
  as unavailable; editing is unaffected.
- On iOS and Android the SDK cannot restart inside a running app: after turning
  statistics off and on again, restart the app to resume reporting.
- Statistics stop when you turn them off; requests already sent cannot be
  recalled.
