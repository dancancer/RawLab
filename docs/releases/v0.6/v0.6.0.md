# RawLab v0.6.0

Master recipes and cross-platform color controls, version `0.6.0`, build `10`.
All four clients retain the earlier effects, GPU denoising, local edit memory,
batch export and shared LibRaw 0.22.2 compatibility patches.

## What's New

- Fourteen master recipes use shared calibrated parameters, LUTs and style
  artwork on macOS, iOS, Android and Windows. Reference-based LUT refinements
  preserve each look; constrained HSL refinements are included where accepted.
- Applying a recipe replaces exposure, shadows, highlights, contrast,
  saturation, tint and all 24 HSL values, resetting strength to 100%. The
  0-200% strength scales the current editable values and LUT together. Manual
  changes, recipe identity and strength survive saved edits and frozen batches.
- An eight-channel HSL mixer and one-shot Auto exposure are available on all
  four clients. New edits default to embedded-preview exposure matching;
  existing records retain their saved exposure baseline.
- iOS supports iPad with adaptive portrait, landscape and narrow-window
  layouts. Its highlight direction, parameter ranges and steps now match
  macOS while preserving legacy native values in existing saved records.
- Film and recipe lists use direct dragging on mobile. Desktop overflow
  arrows appear only when needed and disable at the corresponding endpoint.
  Recipe artwork sits above the name and secondary description without a frame.
- Recipe tint is resolved against each target RAW's as-shot white balance,
  including frozen batch replay, while custom temperature remains independent.
  Older macOS version-2 recipe records preserve independent HSL until reapplied.
- macOS invalidates RAW rendering and white-balance caches when a same-path
  file changes even if its size and modification time remain unchanged.
- HSL lightness offsets fade near gray on CPU and all GPU backends, preventing
  numerical hue differences from becoming brightness speckles under strong HSL.

Temperature, S-curve, sharpening, denoising, vignette and grain are independent
of recipe strength. Selecting an ordinary film clears the recipe but preserves
visible adjustments. Creative looks are style references, not artist-endorsed
products or exact film emulations; artwork is not an actual LUT preview.

## Signing and Limits

- Android retains the existing release identity for upgrades from earlier
  release-signed packages; it cannot replace differently signed debug apps.
- Windows is unsigned. GPU tests assert actual D3D11 execution; an adapter name
  alone is not compute evidence. Explorer desktop interaction is not certified.
- Mac apps are ad-hoc signed, not Developer ID signed or notarized. Intel tests
  use Rosetta; native Intel hardware and physical macOS 15 are untested.
- **The unsigned iOS IPA cannot be installed directly.** Re-sign the app and
  embedded framework with your own valid certificate and provisioning profile.
  This is not App Store/TestFlight distribution. Simulator tests do not establish
  physical iPhone/iPad GPU behavior, memory or thermal performance.
- GPU Auto retains CPU fallback; creative LUTs do not imply GPU execution for
  every look. RAW decoding, noise calibration and file encoding remain CPU work.
  Numerical comparisons use tolerances, not cross-driver bit identity.
- Low-memory devices and every camera mode are not covered. Nikon HE* remains
  unsupported rather than exporting damaged images. No GitHub Actions workflow
  is configured; local passing tests are not CI results.

Original project code remains `GPL-3.0-only`; third-party and historical notices
are retained. Personal RAWs, reference photographs, model weights, signing keys
and credentials are not distributed. Clients have no new model runtime.
