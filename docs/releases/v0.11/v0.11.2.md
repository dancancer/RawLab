# RawLab 0.11.2

Version `0.11.2`, build `22`.

This is an Android and macOS hotfix for issues discovered in 0.11.0 and 0.11.1.
Windows and iOS packages remain at 0.11.0 and are not republished here.

## Fixed

### Android

- **Tile aspect ratio and alignment**: `DetailOverlayTiles` now projects tile
  bounds against the unclipped `photoFullImageRect` via `detailTileDstRect`
  rather than the viewport-clamped `photoImageRect`, keeping tile aspect ratios
  and positions aligned with the zoomed base canvas when panning beyond screen
  edges.
- **Flickering tile cache thrashing**: `EditorViewModel` increases the ROI tile
  cache ceiling to `64 MiB` / `24` tiles, retains currently visible tiles ahead
  of overscan via reverse-order LRU touching (`touchDetailTiles`) and
  budget-aware `planDetailTiles`, and guards `inFlightDetailTileKey` resets with
  `revision == currentRevision`.
- **Sticky native viewport ROI**: `ViewportRoiScope` in `rawlab_jni.cpp` now
  clears the session ROI using an explicit `enabled = 0` struct instead of
  `nullptr` (which `sony2fuji_session_set_viewport_roi` rejected as an invalid
  argument), preventing prior ROI tiles from leaking into subsequent full-preview
  renders.

### macOS

- **Left-sidebar photo tree thumbnails missing or stalling**:
  - `MacEditedPhotoPreviews` removes `.attrib` (`NOTE_ATTRIB`) from the
    `DispatchSourceFileSystemObject` watch mask so thumbnail reads updating
    `atime` no longer self-trigger false invalidations and SwiftUI reload
    livelocks, guards refreshes with `FileStatFingerprint` (excluding `atime`),
    avoids sibling-file refresh storms, and marks
    `MacPhotoPreviewWorker.record(for:)` `nonisolated` so unedited thumbnail
    metadata reads are not head-of-line blocked behind slow edited image
    renders.
  - `PhotoThumbnails.image(for:maxPixelSize:)` adds cancellation-aware waiter
    tracking (`WaiterState`, `InFlightEntry`) with `withTaskCancellationHandler`
    so cancelled tile tasks unwind immediately and cancel queued decode
    operations when no waiters remain.

## Upgrade and compatibility

- **Android**: The APK uses the existing 0.11.0/0.11.1 release signing identity
  and can update 0.11.0 or 0.11.1 in place.
- **macOS**: Both Apple Silicon (`arm64`, with DualDn/Restormer GPU AI) and
  Intel (`x86_64`, without AI) packages target macOS 14+ (HDR editing requires
  macOS 15+) and use the fixed self-signed certificate and Sparkle EdDSA update
  signing (`appcast-arm64.xml` and `appcast-x86_64.xml`).
- Edits and the 0.11.0 data format are unchanged. Downgrading to 0.10.x or
  earlier remains unsupported; see the
  [0.11.0 compatibility notes](v0.11.0.md#compatibility-and-known-limits).
