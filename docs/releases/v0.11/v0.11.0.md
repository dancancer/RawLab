# RawLab 0.11.0

Version `0.11.0`, build `20`.

## New and improved

- Import photos wirelessly from Sony cameras. On Android, RawLab finds the
  camera over Bluetooth, joins its Wi-Fi with system approval, and lets you
  browse, preview and choose photos before importing them into the editor or
  a collection. The camera is only read; nothing on it is deleted, formatted
  or reconfigured. Originals are saved once to the system media library under
  `Pictures/RawLab/Camera/`, grouped by capture day, capture month or not
  grouped. The same camera features on iOS are a preview in this release.
- One-tap incremental import brings in only the photos taken since the last
  import. It can import RAW, JPEG or RAW + JPEG, and JPEGs can be saved as
  received or resized and recompressed on the phone in both manual and
  incremental import. After a disconnect the task resumes from the exact
  previous boundary. Files that are already saved are checked by sampling and
  not downloaded again. A photo that keeps failing is marked and skipped so
  the rest of the batch can finish. iOS camera import adds newest-first
  sorting, optional Photos auto-save, and hardened BLE/Wi-Fi fallback across
  Android and iOS.
- Wireless tethered shooting shows a live view, fires the shutter from the
  phone and receives new photos automatically, including photos taken with
  the camera's own shutter button. On iOS and Android, tethering supports
  tap-to-focus, live-view focus frames with lock confirmation, and focus area
  controls. It has been verified with a Sony α7C II (firmware 2.00), and an
  initial ZV-E10 profile is included.
- Processing version 3 changes how the basic controls respond. Highlights and
  shadows now follow local illumination, and contrast, black and white points,
  vibrance, clarity and dehaze have been retuned. SDR exposure now ranges
  ±5 EV on all four clients; HDR stays at ±4 EV. New edits use version 3.
  Existing edits are upgraded in the background only when the result closely
  matches the original across the whole image, and you can roll back any
  upgrade.
- Photo browsers on all four clients mark edited photos with a pencil and show
  thumbnails with your adjustments applied. iOS and Android add All, Edited and
  Unedited filters. iOS adds Recently Opened, which keeps up to 100 photos
  (about 2 GiB of local originals) across restarts.
- The mobile editor is reorganized into compact tool workspaces, and each tool
  has its own Apply and Cancel. Tone curves gain separate red, green and blue
  channels in SDR and HDR, and lens correction has its own vignetting switch.
  Desktop clients keep, render and copy these settings.
- Mobile zoom on iOS and Android adds 1:1 native viewport ROI tiling and
  progressive detail rendering, keeping full-resolution zoom crisp without
  mosaic artifacts or flicker.
- Mobile HDR export gains cancellable progress reporting.
- Sony RAW files shot in 4:3, 16:9 or 1:1 now develop the full sensor area.
  Existing edits keep their saved framing.
- Rendered DNG exports are now 16-bit integer linear images with an embedded
  sRGB thumbnail and preview, so more third-party viewers can open them.
- When you paste adjustments to a photo that can't use a noise reduction
  setting, that setting is skipped with a notice instead of the paste failing.
  When the source and target use different processing versions, the target
  keeps its own version and you are told.
- PNG exports now write to a temporary file first, as JPEG and DNG already
  did, to preserve an existing destination if the export fails. Cancellation
  support varies by export path.
- Native-size processing is no longer stopped at 128 MP. Image dimensions are
  checked before decoding against an overflow limit of about 2.1 gigapixels;
  available memory still applies.
- Storage is cleaned up automatically. Batch export files are kept for 30 days
  or the latest 100 jobs, and tethering records for 90 days. Camera originals
  are never removed automatically; Settings has a manual cleanup option for
  them. Android can also clear the copies it keeps of photos opened from other
  apps.

## Fixes

- One unreadable edit record, batch journal, preset or look no longer makes
  the whole library unusable. The unreadable entry is listed separately and
  can be deleted; everything else stays usable. Corrupt root edit stores are
  quarantined without blocking the rest of the library, and iOS cleans up
  temporary atomic-write files.
- Resetting SDR adjustments no longer changes the HDR rendition, and resetting
  HDR no longer changes SDR. On all clients, the HDR rendition controls can be
  reset as a group, and each slider resets with a double-tap.
- Pasting into a RAW photo no longer replaces its RAW-only settings with
  placeholder values from an ordinary image. Recipes pasted onto HDR photos
  scale correctly and keep the RAW exposure baseline.
- X3F batch exports use each file's own saved rendering mode. Switching to
  Normal clears every lens correction, and Windows repairs older X3F records
  when they load.
- If a JPEG is only partly written, the export reports an error. HDR exports
  keep the destination's file permissions, and copied EXIF metadata has a size
  limit.
- Camera imports recover from disconnects: queues resume and brief read errors
  are retried. iOS saves import records per photo and removes leftover folders.
- iOS keeps your Photos edits when the same image is imported again and asks
  before restoring an older edit. If an adjustment would discard a JPEG's HDR
  gain map, the original file is saved instead.
- Force GPU unsupported-operation diagnostics and D3D11 bounds are aligned
  across clients. Failed AI denoising initialization rolls back cleanly instead
  of leaving AI enabled, and X3F bridge panic diagnostics and buffer/pixel
  bounds are hardened.
- Windows updates: manually installed copies now detect new releases. An
  untrusted package or a failed check no longer locks the editor. A failure
  to start Update.exe is reported separately from an interrupted install, and
  downgrading the updater no longer locks the editor. Unhandled errors are
  logged instead of closing the app without a message.
- On macOS, a failed update no longer locks the editor, and thumbnails refresh
  after edits while staying within a memory limit. Full-image reference frames
  are now limited to 4,096 pixels on the long edge. Additional macOS and iOS
  editor reliability, value-wheel centering and HDR fixes are included.
- On Windows, a preview error shows a fallback image instead of failing, and
  the interface does less file work on its main thread. The D3D11 renderer
  recovers after the graphics device is lost and processes large photos in
  tiles, with additional fixes for HDR display, cache locking, preview
  cancellation, UI save blocking, Reset All and frozen collection export
  commit/rollback.
- On Android, reliability, R8 release packaging, import cursor handling and
  single-photo export progress tracking are improved.

## Performance

- Exporting a large RAW after previewing it no longer decodes the file again.
- Whole-image CPU processing now runs in parallel and produces identical
  results.
- libjpeg-turbo SIMD acceleration is enabled on all platforms.
- Standalone LUTs make fewer copies of the whole image, 3D LUT parsing is
  faster, HDR downscaling uses prefiltered scaling, and large images benefit
  from a streaming tile cache.
- Mobile HDR export is faster.
- AI denoising uses lower memory residency with enforced Core ML GPU placement,
  and Apple image loading avoids redundant decodes.
- Noise reduction and GPU processing stop sooner when cancelled.
- Android no longer processes one photo at a time when several are being
  rendered.
- iOS reads a RAW file's image data only once during export and caches edit
  records.

## Compatibility and known limits

- Downgrading is not supported. Edits saved by 0.11.0, including processing
  version 3 and the new curve and lens settings, are not supported by 0.10.x
  or earlier. Rollbacks after a processing upgrade work only within 0.11.0.
- Camera import and tethering are available only on iOS and Android, only for
  Sony cameras, and only over Wi-Fi. macOS and Windows cannot import from
  cameras. Tethering takes single still photos while RawLab is in the
  foreground; tap-to-focus and focus area controls are available in RawLab
  tethering while exposure and drive mode remain on the camera. Other Sony
  models can be found and connected, and features are enabled according to what
  each camera reports. The release package provenance lists the cameras and
  devices actually tested.
- iOS camera import and tethering are a preview and have not been tested with
  camera hardware. iOS joins the camera's Wi-Fi automatically only when the app
  is signed with the Hotspot Configuration and Access Wi-Fi Information
  entitlements.
- The red, green and blue curve channels can be edited only on iOS and Android.
  SDR channel curves are processed on the CPU; with GPU set to Force they are
  reported as unsupported instead of running on the CPU.
- An existing edit is upgraded to processing version 3 only if it passes the
  check. Otherwise it keeps its previous version and settings.
- Processing very large images at native size still depends on available
  memory. Behavior near the 2.1-gigapixel limit has not been tested on Windows
  or iOS devices.
- The HDR, ProRAW, AI denoising, X3F and raster input limits in the
  [0.10.0 release notes](../v0.10/v0.10.0.md#compatibility-and-known-limits)
  still apply, except that Android can now clear the copies it keeps of photos
  opened from other apps.
- Mac installers still use the fixed self-signed certificate and Sparkle EdDSA
  signing. Windows automatic updates work only with the current-user Setup
  installer. The unsigned iOS IPA must be signed and provisioned by the user.
