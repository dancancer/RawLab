# Rebuilding RawLab v0.8.1

Use the exact `v0.8.1` tag or corresponding source archive from
[the release](https://github.com/dancancer/RawLab/releases/tag/v0.8.1).
All four clients use `0.8.1`/build `13`. `BUILD-PROVENANCE.json` records the actual
built commit/tree, final tag and every asset's size, SHA-256 and verification.

`RawLab-0.8.1-source.tar.gz` contains the tagged project tree plus pinned
dependency sources. `LibRaw-0.22.2-patched-source.tar.gz` provides the matching
patched decoder and CMake support. Original RAWs, user profiles, signing keys,
passwords and unrelated build outputs are not part of the source packages.

## Dependencies

Retain the exact versions, source checksums and patches in the repository:
LibRaw 0.22.2, Adobe DNG SDK 1.7.1 Build 2724/JPEG XL dependencies, libtiff 4.7.1,
Lensfun 0.3.4 with the vendored DB1 snapshot and pinned GLib/PCRE2, OpenCV 4.12.0
with matching contrib and patched wavelib. Source URLs/checksums are in the
existing CMake and platform dependency scripts; do not substitute an older
LibRaw installation or a compiled cache from a different source/configuration.

## macOS

Use Xcode or compatible Command Line Tools, CMake and pkg-config. Build each
architecture separately with deployment target 14.0:

```sh
RAWLAB_ARCH=arm64 MACOSX_DEPLOYMENT_TARGET=14.0 \
  RAWLAB_BUILD_DIR="$PWD/lutools/build-release-v081-arm64" \
  RAWLAB_APP_PATH="$PWD/build/release-v081-arm64/RawLab Mac.app" \
  bash RawLabMac/build.sh
```

Repeat with `x86_64` and separate output paths. The scripts share checksum-verified
downloads but isolate compiled dependencies by architecture/minimum OS. They
embed runtime libraries, LUT/artwork, six-language resources, Lens DB and notices,
then ad-hoc sign and verify the bundle. They do not notarize or use Developer ID.
Targeting 14.0 does not claim a physical macOS 14 acceptance result.

## iOS

Use full Xcode:

```sh
IOS_DEPLOYMENT_TARGET=18.0 bash lutools/platform/ios/build-framework.sh
bash lutools/platform/ios/verify-framework.sh lutools/build-ios/sony2fuji.xcframework
xcodebuild -project RawLab/RawLab.xcodeproj -scheme RawLab \
  -configuration Release -destination 'generic/platform=iOS' \
  -derivedDataPath build/ios-release-v081 \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build
```

Framework slices are device arm64 and simulator arm64/x86_64. An app zipped
under `Payload/` is still unsigned and cannot be installed directly. Use your
own valid certificate and provisioning to sign the app and embedded framework;
see the [iPhone guide](../ios-installation.md). No Store/TestFlight delivery or
physical-device acceptance is implied by the unsigned build.

## Android and Windows

- Use the existing [Android toolchain guide](../../RawLabAndroid/README.md).
  `RawLabAndroid/scripts/build-release.sh` requires the existing external
  keystore/password-file environment variables. It builds Release, zipaligns,
  signs and verifies the APK and checks native 16 KiB alignment. The official
  certificate remains SHA-256
  `9fd68e245a597cde2abb949ff807819a89afdd4b000b5ad02391181f38a06048`;
  do not generate a replacement key for an update.
- On a prepared Windows x64 host run `RawLabWindows/build.ps1 -SelfContained`.
  Keep the entire `build/RawLab-Windows` directory when packaging. Use its
  existing tests and [Windows guide](../../RawLabWindows/README.md); do not
  weaken execution policy or omit runtime/ExifTool/license resources.

## Usage-Statistics SDK

Release builds of all four clients include the Alibaba Cloud RUM SDK covered by
the [linking exception](../../LICENSE-ALIYUN-RUM-EXCEPTION): macOS/Windows PC
SDK 0.4.4, iOS 2.4.2 and Android 2.3.2. The SDK binaries are not in Git or the
source archive. The build scripts download them from the vendor's versioned
URLs into the main checkout's `.cache/shared/aliyun-rum/` and stop on any
SHA-256 mismatch:

- macOS: `RawLabMac/build.sh` calls `scripts/rum/prepare-macos.sh`; set
  `RAWLAB_RUM=0` for a package without statistics.
- iOS: run `bash scripts/rum/prepare-ios.sh` before the Release build; Debug
  builds do not link the SDK.
- Android: run `bash RawLabAndroid/scripts/fetch-rum-sdk.sh`; pass
  `-PrawlabRumRelease=false` for an offline release without statistics.
  `build-release.sh` refuses to sign an APK that lacks the SDK.
- Windows: `build.ps1` fetches the archive itself; `-RumSdkZip <file>` uses a
  local copy and `-NoRumSdk` builds without statistics.

Debug builds never include the SDK.

## Windows Package Assembly for v0.8.1

The shared processing core, LibRaw and every other native dependency are the
same source as v0.8.0 (`git diff v0.8.0 v0.8.1 -- lutools` changes only an
ignore rule). The v0.8.1 Windows ZIP therefore reuses the v0.8.0 package's
native files byte for byte (`sony2fuji.dll`, `sony2fuji.exe`, `raw.dll`, the
Visual C++/OpenMP runtimes, ExifTool and native license files) and replaces
the self-contained .NET application, resources, notices and the RUM SDK with
a fresh `dotnet publish` of the v0.8.1 source. Hosted CI still builds the full
Windows package from source with `build.ps1 -SelfContained` and runs its
suites; `BUILD-PROVENANCE.json` lists which files came from which build.
`build.ps1 -SelfContained` on a prepared host remains the supported way to
rebuild everything from source.

External RAW fixtures are optional local tests and must not enter packages.
The bundled look notices and 28 third-party `UNCONFIRMED` fields are retained;
the owner's formal-release decision does not clear underlying third-party
permission.
