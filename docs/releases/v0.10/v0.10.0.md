# RawLab 0.10.0

Version `0.10.0`, build `19`.

## New and improved

- HDR editing on macOS, iOS, Android and Windows adds automatic exposure,
  black and white points, S and custom luminance curves, vibrance, eight-range
  HSL with photo sampling, and shadow/midtone/highlight color grading. Vignette,
  grain, sharpening, clarity, dehaze and image-level noise reduction are also
  available. An HDR peak limit and separate SDR-base exposure, contrast and
  saturation controls let users adjust both renditions.
- HDR looks include explicitly declared HDR CUBE LUTs with adjustable strength,
  HDR Silver and the HDR Silver Master recipe. Camera RAW HDR adds camera-space
  white balance, exposure-reference selection, calibrated lens correction,
  Bayer FBDD and compatible D65 camera profiles. Apple Silicon macOS and
  Windows can use GPU AI denoising for compatible Bayer RAW in HDR editing.
  Copy/paste, presets, synchronization and per-photo batch export carry the
  supported HDR settings.
- macOS and iOS can export HDR HEIF when the system encoder and readback checks
  support it. iOS ProRAW JPEG export uses runtime decoder, encoder and resource
  checks instead of a fixed iPhone model, OS major version or sample-size gate.
- macOS and Windows gain Edit, Select and Preview workspaces, with a full-height
  photo canvas between the file browser and adjustment inspector. Folder
  navigation and photo thumbnails are separate, folder scroll positions are
  remembered, and narrow panels keep sliders, HSL and denoising controls usable.
  Switching between fit and actual pixels reuses completed previews where possible.
- Open photos through the system on every client. macOS Open With and file
  drops open one photo in the editor or several in a collection. iOS accepts
  document-open URLs and file drops. Windows forwards files from another launch
  to the running app. Android accepts Open With and single/multiple-photo
  shares, retaining a private copy so temporary access can end safely.
- Reopen opaque 16-bit integer RGB PNG on all four clients, including RawLab's
  own exports. macOS, iOS and Windows also accept 16-bit RGB TIFF, including
  supported Sigma Photo Pro files with an embedded preview. Color conversion
  and orientation preserve the high-bit-depth editing input. Windows adds SDR
  HEIF/HEIC import; Android supports SDR HEIF on Android 9+.
- Desktop Agent and MCP recipes support the expanded HDR controls and looks,
  camera RAW and ProRAW sources, and HDR JPEG or SDR JPEG/PNG/rendered-DNG
  output. Camera RAW recipes can specify white balance, exposure reference,
  FBDD, lens correction and a compatible camera profile. X3F recipes preserve
  the selected rendering mode. MCP can export to filesystems without hard-link
  support while preserving existing destination files.
- iOS detects photo formats from file contents when extensions are missing or
  misleading and keeps the selected filename in the editor. Local error reports
  can be exported from an error alert or the More menu; they retain up to 64
  diagnostic events without photo bytes, filenames or full paths.

## Fixes

- Ordinary edits no longer stop because an on-disk adjustment revision differs
  or a global reload lock is active. Each editor commits within its current
  session. A failed save keeps the adjustments available for retry, and older
  edit records remain readable.
- iPad SDR JPEG previews adapt to screen size and zoom, reaching a 4,096-pixel
  long edge after interaction settles instead of staying at 1,280 pixels.
  iOS photo-library imports consistently retain RAW or gain-map originals and
  find saved edits across photo-entry points. Collection export offers HDR JPEG
  for eligible photos; JPEG export also handles RAW originals whose metadata
  ImageIO cannot describe, retaining output size and orientation.
- macOS 14 can open supported ISO/Adobe gain-map photos as SDR with a notice,
  while retaining saved HDR settings for use on a supported system. macOS mixed
  collections can use HDR JPEG for HDR edits and JPEG for the rest. Ordinary
  raster batch targets no longer fail because AI denoising was selected on
  the source; macOS and Windows export those targets without AI denoising.
- Supported Merrill X3F files use their saved camera color mode and supported
  tone settings in Normal Development, including Vivid and Portrait. New X3F
  imports use Normal where supported and the existing Legacy decoder otherwise.
  DCP import on all four clients can accept an external JSON tone curve or an
  explicit choice to omit automatic black adjustment when the embedded curve
  is missing.
- Pasting, presets and synchronization from RAW to ordinary images accept
  neutral camera white-balance and exposure-reference fields without rejecting
  the other adjustments. Active RAW-only adjustments remain subject to checks.
- Android accepts supported Motion Photo/video trailers and C2PA metadata in
  ordinary JPEGs without treating them as unsupported multi-image content.
- On Windows, opening a photo shows its embedded thumbnail until the first
  preview is ready instead of a blank canvas, and ordinary images keep the
  RAW-only lens correction entry disabled. Cancelling a batch export finishes
  the photo in progress before stopping, as on macOS, and Reset All with an
  unapplied geometry or lens change no longer reopens the editor with the
  pre-reset draft. Saving adjustments no longer fails when another part of
  the app is reading the local edit records at the same moment.
- Photos with a missing HDR look or camera profile can open with a warning;
  export still validates the required resources.

## Compatibility and known limits

- Camera RAW HDR requires a supported Bayer/X-Trans linear decode path. Linear
  DNG outside the ProRAW path, layered sensors and the current JPEG XL DNG
  decoder are outside this scope. See the [camera RAW scope](../../design/hdr-photos/camera-raw.md).
- Apple ProRAW uses Core Image on macOS/iOS and the Adobe DNG SDK on
  Android/Windows, so the same photo can render differently across decoder
  families. Large exports still depend on available memory and temporary disk
  space. HEIF and rendered DNG use full-frame processing and runtime resource checks.
  See [ProRAW support and export limits](../../design/hdr-photos/proraw.md).
- HDR looks require an HDR CUBE or compatible HDR recipe. Legacy film looks,
  SDR LUTs and SDR recipes remain available in SDR editing. HDR camera profiles
  use a matching camera's fixed D65 matrix; profile tone curves, HueSatMap,
  LookTable and multi-illuminant interpolation are not applied. Selecting a
  camera profile disables HDR AI denoising on macOS and Windows.
- HDR processing uses the CPU apart from the supported desktop RAW AI stage.
  AI denoising requires a hardware GPU and compatible models; Intel Mac, iOS and
  Android do not include it. There is no CPU neural-inference fallback. Models
  retain their separate noncommercial licenses; see [licensing](../../reference/licensing.md).
- Normal X3F rendering uses the CPU without AI denoising or additional lens
  correction. Merrill sharpness, Fill Light and color-wheel settings remain
  unsupported. See the [X3F scope and limits](../../../lutools/docs/x3f-rendering.md).
- Mac HDR editing/export requires macOS 15+. The macOS 14 SDR fallback excludes
  Apple auxiliary gain-map photos. HDR display requires a compatible system
  and screen; Android requires API 34+ and Windows uses FP16/scRGB where
  available. Physical HDR brightness, minimum-OS behavior and device resource
  limits require separate acceptance; package provenance records actual coverage.
- HDR HEIF export is limited to supported macOS/iOS runtimes. Android and
  Windows export HDR as gain-map JPEG. Direct PQ/HLG HEIF input is unsupported.
- Ordinary high-bit-depth input is limited to opaque integer SDR RGB PNG/TIFF.
  General multi-page TIFF, BigTIFF on Windows, floating-point images and actual
  transparency remain unsupported. Android does not import TIFF and limits
  PNG16 decoding to 32 MP; other supported raster inputs have a 128 MP decode
  budget, subject to device memory. Android PNG16 also has stricter ICC profile
  limits. See the [raster input contract](../../../lutools/docs/color-contract.md#display-referred-raster-input).
- Agent/MCP HDR previews are SDR PNG, not HDR display previews. ProRAW recipes
  require a CLI build with DNG SDK support; capability discovery identifies
  available recipe versions, inputs and outputs. Mobile Agent interfaces are
  outside this release. On filesystems without hard links, an MCP export may
  be visible while it is being written.
- Android keeps private copies of system-opened/shared photos without an
  automatic cleanup policy. Available storage still limits imports.
- Mac installers retain the fixed self-signed certificate and Sparkle EdDSA.
  Windows automatic updates use the signed descriptor and require the
  current-user Setup. The unsigned iOS IPA requires valid user signing and
  provisioning.
