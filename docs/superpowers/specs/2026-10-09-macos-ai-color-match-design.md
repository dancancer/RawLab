# macOS AI 仿色与本地 LUT 生成

状态：用户已确认执行（含 CUBE 分享导出），并批准 display-sRGB CUBE 修订。实现和自动验证已落实；原生界面人工验收与真实风格参考审片尚未完成，详见[验收记录](../../verification-macos-ai-color-match-2026-10-09.md)。

2026-10-09 实施前置检查：恒等配方的 65/129-grid 原生中性 CUBE 均未通过 0.02 最大误差门槛。
详见[验证记录](../../verification-ai-lut-bake-2026-10-09.md)。用户随后明确同意采用下文的 display-sRGB CUBE 路线；中性显影不再烘焙进 LUT。

## 已确认范围

- 首先支持 macOS，对当前打开的 RAW 照片仿色。
- 用户提供一张或多张风格参考图，可补充文字要求。
- 用户自行填写 API 地址、模型和密钥，首先验证 DeepSeek。
- 采用方案 3：AI 返回受约束的颜色变换，本地生成可被 RawLab 接受的 CUBE。
- 生成的自定义 CUBE 支持保存到用户选择的位置和 macOS 系统分享；无需先应用到当前照片。
- 不做无目标照片的通用风格提炼、统一服务、其他平台 UI 或发布部署。
- 密钥不提交、不打包、不进入照片编辑记录。开发联调可显式读取被忽略的根目录 `.env`；正式应用使用 Keychain。

以下具体行为和工程设计包含已获用户确认的色彩路径修订。

## 用户流程

1. 当前照片完成精确预览后，从工具栏或菜单打开“AI 仿色”原生工作表。
2. 首次使用配置服务。默认地址 `https://api.deepseek.com`，默认模型 `deepseek-flash`，两者可编辑。
3. 添加 1-6 张参考图，显示缩略图，可移除；可填写一段风格要求。多图默认共同提炼风格，不根据文件大小或图片像素数自动加权。
4. 显示实际目标服务主机、发送图片数量和上传告知。用户点击生成后才发送照片；仅打开面板、添加图片或修改配置不上传。
5. 生成期间显示准备图片、请求 AI、生成 LUT、校验、渲染预览等真实阶段，可取消，不显示虚构进度百分比。
6. 在工作表中并排查看“原编辑”和“AI 候选”；另可切换到“中性基线”。参考图保留在可滚动缩略条中。
7. 调节候选强度，或输入补充要求后点击“继续调整”。每次主动生成或调整只发起一次推理请求，不后台无限试错。
8. 点击“应用”才写入托管外观库并更新当前照片；取消、关闭、失败都不改变原编辑。
9. 校验和候选渲染成功后，可独立选择“导出 CUBE…”或系统分享；已保存的 AI 外观也提供同样的操作。导出或分享不隐式应用、不重新请求 AI。

复用 SF Symbols、原生文件选择器、文本框、滑杆和状态反馈。工作表在主窗口最小 950x620 尺寸下可滚动，不遮挡底部确认/取消操作。缩略图保持比例，不裁掉参考图的主体来适配装饰性布局。

## 编辑语义

本版是从当前照片生成一个新的完整外观，不是在当前胶片上再叠加滤镜。

- 开始生成时冻结 RAW 文件身份、编辑状态、当前外观副本和请求 ID。
- 生成输入基线：保留当前曝光基准、曝光、RAW 白平衡和细节设置；不选择胶片，输出对比度、高光、阴影、S 曲线、饱和度恢复中性值。
- 基线必须重新精确渲染。不能直接使用现有 `model.neutral`，因为它仍包含当前输出调整；也不能发送未完成的交互代理或相机内嵌 JPEG 冒充基线。
- AI 修改的是基线之上的颜色映射，不修改 RAW 白平衡、曝光基准、降噪或锐化，也不把这些参数写入 LUT。
- 候选使用新 CUBE，默认强度 100%；保留输入与细节设置，输出明暗和色彩滑杆归零，避免二次调色。
- “原编辑”保留原来的胶片和所有滑杆值。“应用”界面明确显示新外观会替换旧外观，以及哪些滑杆将归零。
- 保留一次应用前编辑快照，提供恢复此次 AI 应用前状态的动作。后续手动编辑不被异步生成结果覆盖。
- 关闭、换片、文件身份变化或新请求启动时，旧请求失效；即使远端随后返回，也不能应用到其他照片或更新后的编辑状态。

现有强度控件的 0% 代表中性基线，100% 代表生成外观；不是原编辑与候选之间的混合。应用后沿用现有 0-200% 范围，不修改全局强度语义。

## AI 输出契约

模型只输出版本化 `AIColorRecipe` JSON。名称、说明、变换参数相互分开；不接收代码、表达式、路径、URL、任意矩阵或整张 CUBE 数值表。

第一版只提供一套固定顺序的解析调色模型：

1. 固定横坐标的单调明度曲线。
2. 全局彩度系数。
3. 固定八个色相区间的色相偏移、彩度倍率和明度偏移。
4. 阴影、中间调、高光的色彩偏移。
5. 固定的输出色域处理和 sRGB 编码。

参数作用于中性显影后的显示色彩，不含空间坐标、语义遮罩、颗粒、锐化或局部曝光。以现有实验的 Oklab 处理经验为参考，使用明确的显示线性 sRGB / Oklab 转换及连续的色相、明度权重；不能把场景线性值直接当显示色彩。

首版数值约束：

| 字段 | 约束 |
| --- | --- |
| `version` | 固定为 1，未知版本拒绝 |
| `name` / `summary` | 非空短文本，分别最多 80 / 600 字符，不参与路径或 CUBE 语法拼接 |
| `tone` | 9 个纵坐标，横坐标固定为 0、0.125 至 1；有限数且在 0-1 内，相邻段斜率在 0.05-4；黑端不高于 0.1，白端不低于 0.9 |
| `chroma` | 0-2，1 为不变 |
| `hueBands` | 固定 8 项，Oklab 色相中心为 0、45 至 315 度；各项偏移最多正负 30 度、彩度倍率 0-2、明度偏移正负 0.08 |
| `toning` | 固定阴影/中间调/高光三项，每项 Oklab a/b 偏移均在正负 0.03 内 |

默认曲线为恒等曲线，色相/明度/染色偏移为 0，彩度倍率为 1。默认配方的直接解析结果必须在浮点容差内等于中性显影，不能因“保护”或色域处理默认增加风格；离散 CUBE 另受下述采样误差门槛约束，不宣称逐像素相等。具体连续权重公式、色域收敛算法和独立数值锚点在实施计划中固定，不交给模型选择。

近灰区域的分色相调整连续衰减；分区染色是显式操作，可以改变灰色。所谓肤色保护只可作为有限色相区间的保守参数策略，不能宣称具有人脸识别或语义肤色遮罩。

Swift 负责 JSON 结构及字段校验；原生编译器再次校验数值、版本和结构边界。不把越界输出静默裁成合法值，不从自然语言中猜测缺失字段。未知字段、非有限数、缺项和截断响应都返回可重试错误。

多张参考图风格冲突时，允许模型通过短说明提示冲突并生成保守折中，但不返回无依据的“匹配百分比”。继续调整时发送基线、当前候选、参考图、当前配方及用户补充要求，并要求返回完整的新配方，不累乘旧配方。

## 本地 CUBE 编译

采用确定性的原生 C++ 编译模块，不在应用中启动 Python、安装 OCIO 或调用外部命令。网络和密钥处理保留在 Swift，编译器本身不联网。

编译顺序：

```text
显示 sRGB 网格
  -> AIColorRecipe 的显示域颜色变换
  -> 显示 sRGB CUBE
```

默认 65-grid，标准 R-fast 存储和 0-1 DOMAIN；头部声明 `#Gamma:sRGB to sRGB` 与 `#Gamut:ITU-R BT.709 to ITU-R BT.709`。只有这类明确声明的显示域 CUBE 进入新路径，旧 Log CUBE 和 DCP 行为保持不变。

编译器放在 `lutools/src/core`，复用既有 sRGB 传递函数，通过新增的窄 C ABI 供 Swift 调用。核心新路径复用 [neutralDisplay](../../../lutools/src/core/photo_rendering.h)，不复制或改变中性显影公式。C++ parser 虽然可读取最高 256-grid，本功能只生成 65/129 两档，不扩大默认资源开销。

RAW 曝光基准、用户曝光、RAW 白平衡在运行时仍由原引擎处理一次。CPU / Metal 先精确中性显影，再查显示域 CUBE，最后继续走现有强度、输出调整、细节与导出路径。新类型没有额外中性曲线。

新增独立、版本化的生成入口，不改变现有 PHOTO 请求结构或 `.rlook` 格式。复用 CPU / Metal 插值实现，为显示域类型增加输入分支，不在 GPU 实时解释 AI 配方。GLES / D3D11 尚未实现新类型时显式返回不支持，Auto 回退 CPU，Force 报错；不能静默当 Log LUT 执行。

### 误差与发布门槛

- 写到任务私有临时文件，重新读取已序列化 CUBE，使用原生三线性插值与直接解析结果比较。
- 测试样本含确定性的完整显示 sRGB 域、灰阶和色相/明度渐变，分别记录最大、p99、均值误差。真实 RAW 另验证先中性再查表的结果，不能把编译采样误差称为照片匹配精度。
- 初始硬门槛沿用准备工具的最大显示通道绝对误差 0.02。它是离散采样门槛，不是 Delta E，也不代表风格相似度。
- 65-grid 未通过时只尝试一次 129-grid；仍失败则不安装候选，不放宽阈值或隐藏失败。
- 第一阶段验证恒等配方、代表性调色配方和边界参数能否通过；合法但过于陡峭的配方在 129-grid 仍超限时明确拒绝，不能声称增加网格必然解决。
- 所有表值有限、输出 SDR 范围明确，检查灰阶反转、渐变断层、色相环连接和高光裁切。色域压缩不得改变已经合法的恒等颜色。
- 文件通过 `sony2fuji_validate_look` 后才可渲染候选；成功导入不替代插值误差检验或真实照片审片。

面向任务模型只暴露生成候选、调整候选、取消和应用所需操作；不提前建立多供应商插件框架。HTTP 会话可注入测试替身；将来统一服务只替换请求部分，仍返回相同配方契约。

候选阶段不调用会立即改变 `selectedFilmID` 的现有导入动作。确认后先安装外观，再保存单个完整编辑状态并发布到 UI；任一步失败保持原编辑可用。刚安装但未成功关联的文件只清理本任务拥有的资源，不能删除其他照片引用的外观。

批准后的 CUBE 用新 UUID 保存在现有托管外观库，沿用现有编辑持久化和批量导出快照，不引用临时文件。将经过校验的配方版本、数值、生成模型和编译误差报告作为有限本地元数据保留；不嵌入参考图、API Key、请求头、源文件绝对路径或完整对话。

保存为托管外观是为了重启恢复和现有功能兼容，不新增“从任意参考图生成通用预设”的入口，也不宣称该外观适合所有照片。现有手动选用或批量导出不因此被禁用。

## CUBE 导出与分享

- 候选预览和已保存 AI 外观的操作菜单均提供“导出 CUBE…”与“分享 CUBE…”。使用原生保存面板和系统分享选择器，不新增云端托管、分享链接或账号体系。
- 导出的是生成外观本身的 100% 强度 CUBE，不把当前预览强度、RAW 曝光/白平衡、后续滑杆微调、降噪或锐化合并进去。操作处明确标注“原始外观 · 100%”，不误称为导出当前照片的全部调整。
- 保持原网格尺寸、DOMAIN 和 RGB 表值，不重新采样或重新调用 AI。输出是独立 `.cube` 文件，接收方在 RawLab 中导入无需 API Key、参考图或伴随 JSON。
- 采用显式的分享文件写出逻辑，只保留安全显示名称、格式/生成器版本和必要色彩约定；不直接复制含内部元数据的文件。保留 `#Gamma`、`#Gamut` 和 sRGB 输出说明，不导出配方说明、用户提示词、模型对话、源文件名、绝对路径、参考图片或密钥。
- 导出为显示 sRGB 输入/输出的创意 CUBE。RawLab 会先完成中性显影再使用；其他软件必须提供相同的显示 sRGB 输入语义，不能直接施加于 Log/线性 RAW。不同软件中性显影不同，不能承诺相同照片在所有软件完全一致。文件注释与导出界面均说明输入约定。
- 默认使用清理过的外观名称和 `.cube` 扩展名，用户可改名和选择位置。先写目标目录内的临时文件并校验，再安装到目标位置；覆盖必须经过保存面板确认。禁止覆盖当前 RAW、参考原图、托管外观源文件及其文件别名。
- 系统分享使用同样脱敏的任务私有文件快照，只有用户在系统界面中选择服务并确认后才交给该服务。分享进行中保留快照，即使仿色面板关闭也不提前删除；完成或取消后释放。仅打开分享选择器不代表已成功发送，不报告无法确认的收件结果。
- 无效候选、缺失或损坏的已保存外观不可导出/分享。保存失败、用户取消或分享失败不改变当前编辑或外观库；用户已成功导出的文件不因随后取消仿色而被删除。
- 接收方导入使用已有外观导入流程。分享是已有结果的可携带能力，不等于已实现无目标照片的通用风格提炼，也不保证不同曝光、白平衡或照片内容下视觉一致。

## 图片与网络

- 使用 ImageIO/CoreGraphics 解码、应用方向并按实际 ICC 转换为 sRGB；不能只移除配置文件或把广色域像素标记成 sRGB。
- 首版选择器支持 JPEG、PNG、TIFF、HEIC 静态图片，明确选择单帧；无法解码或转换的文件逐项提示，不能悄悄少传。
- 长边不超过 1600 像素，重新编码 JPEG，不复制 EXIF、GPS、拍摄信息或原始文件名。源照片发送本地显影的缩小图，不发送 RAW。
- 每张编码后最多 2 MiB，请求体最多 24 MiB；解码前检查尺寸与资源限制。普通生成最多 7 张图，继续调整最多 8 张图。
- 正式配置仅接受 HTTPS；密钥按规范化服务地址隔离，改变服务主机时不能自动携带另一主机的密钥。禁止自动跟随携带认证信息的重定向。
- 默认使用 `/chat/completions`，JSON Output 明确要求 JSON；本地仍严格验证契约，不把 JSON mode 当作 schema 校验。
- 网络请求超时 90 秒，响应有独立大小限制。鉴权失败、额度不足、限流、模型不支持图片、空输出、截断、无效配方、编译失败分别反馈。
- 不自动重试计费推理；取消尽快中止本地任务，但不能承诺远端已停止计费。
- “测试连接”只请求模型列表，不发送私人照片；明确区分鉴权成功与多图生成实测成功。
- 不打印密钥、请求体或 Base64 图片；开发联调也遵循这一规则。`.env` 不自动导入用户 Keychain，不随应用分发。

## 验证与完成条件

### 已有证据

2026-10-09 的前置联调已用项目 `.env` 中的密钥访问 DeepSeek：模型列表 HTTP 200，`deepseek-flash` 声明 text/image 输入；两张人工色块图请求 HTTP 200，正确识别橙色源图和蓝色参考图，JSON 与基础参数范围检查通过。约 1.2 秒、657 tokens 仅为该次微型请求，不是照片仿色的速度或价格承诺。

该请求尚未使用本设计配方、原生编译器或应用界面，不证明 LUT 生成成功或照片匹配质量。

### 实施时必须验证

- 配方解析与原生校验：合法恒等值、边界、未知字段/版本、缺项、非有限数、非单调曲线及超限数组。
- 编译：固定输入的确定性、sRGB/Oklab 数值锚点、R-fast 顺序、默认配方与恒等显示值、有限输出、灰阶/色相连续性、误差门槛、65 到 129 的有界升级、失败不安装；原有 F-Log2 锚点回归保留。
- macOS 集成：ICC/方向/元数据处理、假 HTTP 服务的成功/失败/取消、Keychain 按服务隔离、换片/改参数/重复请求的旧结果丢弃、应用/恢复、重启恢复及外观丢失提示。
- 导出/分享：未应用候选与已保存外观均可操作；导出后重新导入的网格、DOMAIN、表值和渲染结果保持一致；100% 外观不受候选强度或当前滑杆影响。检查脱敏头部、名称清理、覆盖确认、源文件保护、失败/取消不修改编辑，以及系统分享文件存活期；重导入不依赖 API Key 或网络。
- 真实 RAW：同一 CUBE 的 CPU / Metal 对照、强度 0/100/200、精确预览与全分辨率导出、JPEG 与 16-bit PNG；降噪原有 CPU 回退语义不改变。
- 用户提供或明确授权的实际目标 RAW 与参考图：至少单参考、多参考两组，保留原编辑/中性/候选对照，人工检查肤色、灰白、高光、渐变和参考风格。没有授权素材则明确该项未完成，不擅自扫描私人照片库上传。
- 核心新增测试、受影响的现有核心检查、Mac 构建及外观库/编辑持久化/渲染/批量导出相关回归；只读其他平台调用契约，不宣称已完成其他平台设备测试。
- 原生应用最小窗口和常用窗口尺寸截图检查；密钥隐藏、参考缩略图、长名称、错误、生成中和确认状态均可正常操作。

完成必须同时包含可用的 macOS 流程、通过校验的 CUBE、导出与系统分享能力，以及实际视觉验证。接口成功、文件可解析、CPU/GPU 一致、插值误差合格、风格接近是五种不同证据，分别报告。

## 非目标与能力边界

- 不进行图像生成、主体替换、局部蒙版、语义分割或自动上传原片。
- 3D LUT 只映射颜色，不能仅给某个同色物体变色，也不能复制纹理、颗粒、光晕或空间光照。
- 非配对参考图不能唯一决定正确调色变换；AI 的首次结果可能需要用户继续调整，不承诺像素级复刻。
- 不新增完整 HSL 编辑器或脚本调色语言，不把本次工作扩展成统一云端服务。
- 不改已有实验数据、不重新校准相机、不改变项目其他正在进行的功能或发布包。
