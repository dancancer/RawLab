# 图像处理版本与旧记录兼容

Mac、Windows、iOS、Android 编辑与 CLI 使用独立的处理身份。旧像素兼容基准是发布版 `v0.8.2`
（`dd5c15bfa5ef14d885ee6c002ab3c516b56d38b0`）及其固定依赖；不承诺复现所有历史版本
的任意输出变化。各平台的运行验证范围与构建结果分别报告，不能从接口存在推断硬件已验证。

## 为什么不能复用现有版本字段

记录格式版本、CLI `schema_version`、C 配置结构的 `version` 和
`masterRecipeSettingsVersion` 各有既定含义，都不是整条图像处理管线的版本。
单独保存降噪强度不能区分SWT 与 C5；降噪关闭也不能阻止 Bayer
去马赛克从 AHD 改为 VNG。因此，字段能读回不等于像素兼容。

## 平台边界

降噪算法不要求所有客户端完全一致。桌面端可以使用更高的计算和内存预算，移动端可以
按机型能力采用不同算法或质量档位。每个算法族及版本必须具有明确身份，不能把不同
实现都标成同一版本后声称像素一致。移动端尚未适配不阻塞桌面候选自身的画质验收。

同一算法版本的 CPU/GPU 路径仍按其数值容差验证；不同算法版本之间比较画质和资源
成本，不以逐像素相等为验收标准。同一端的保存／重开和精确预览／导出保持稳定。

## 采用的兼容策略

- 为编辑记录定义独立的处理身份，至少包含算法族、算法版本与影响像素的质量档位。
  缺字段的记录按该客户端明确冻结的旧处理基准解释，不能默认为加载它的软件的最新算法。
- Mac、Windows、iOS、Android 新建编辑使用版本 2。已有记录的加载、预览、保存、取消修改
  以及普通参数调整不隐式升级；升级处理版本必须是明确操作。
- 旧版本绑定旧 Bayer 去马赛克与旧 SWT，包括采样、尺度、阈值、恢复公式和后端语义；
  新版本绑定获准的候选实现。只保留 AHD 或只保留参数，均不足以复现旧行为。
- 兼容基准必须注明发布版本、源码与依赖来源。无版本的旧记录无法据此恢复所有历史
  软件版本的任意像素变化；承诺范围只能是实际冻结并验证的基准。
- RAW 原图不改写。批量任务快照、CLI recipe、编辑库和导出全部携带处理身份。
  跨端无法执行原算法或档位时，应明确提示并由用户选择转换，不静默降级。

## 共享核心边界

处理身份固定为 `{"family":"rawlab","version":1|2,"quality":"standard"}`。
版本 1 使用 LibRaw 原默认插值选择（普通三色 Bayer 为 AHD）和旧 SWT；
版本 2 使用 Bayer VNG 和 C5 EAW。非 Bayer 输入仍走 LibRaw 原有插值路径。
未知成员、算法族、版本或质量档位均拒绝；不能退回默认并覆盖编辑库或批量日志。

独立的 additive C setter `sony2fuji_session_set_processing_version` 接受
`SONY2FUJI_PROCESSING_LEGACY=1` 和 `SONY2FUJI_PROCESSING_C5_V2=2`。
新 C session 默认版本 1，保护未主动选择新版的调用方，没有调用 setter 的外部宿主也保持旧行为。
无效 setter 不改变已有 session。它不重解释现有配置结构版本，也不改变 request v2
布局。C++ 选项、session 状态与客户端持久化使用一致的身份含义，但每个客户端可以
只支持其中部分算法族或档位，不要求共享全部实现。

`RAWProcessOptions` 的公开默认保留 LibRaw 旧选择；内部降噪入口默认测试
版本 2。组合调用这些低层工具时必须明确选定同一身份；客户端和 CLI 由 C session
统一配置，而不是分别猜测 RAW 与降噪的版本。

RAW 解码、曝光锚点、降噪分析和结果缓存都必须包含相关处理版本，或在切换时完整失效。
旧、新版本交替渲染不能命中对方的像素或噪声模型。精确预览与 FINAL/导出仍不得复用
近似交互结果。

C5 使用六层 EAW、全图统一的样本校准和频带能量、软阈值，以及有限邻域的两遍分块处理。
亮度、色度、粗色斑强度仍独立可调，零亮度和零色度组合为精确旁路。强降噪会压低弱纹理，
用户可以降低强度保留细节；预设不是普适画质门限。低噪声保护依据拟合模型在 0.18 处的相对
标准差：不超过 0.02 时旁路，0.02–0.04 连续放大到全强度。这是工程保护，不是 ISO 或相机标定。
C5 目前只实现 CPU 滤波；Auto 仍可接续平台 GPU 显示渲染，Force 对需要执行 C5 的请求报错。
移动端沿用预览缩放和完整导出两条路径，不在资源不足时静默替换算法；内存分配失败保留输入并报错。

旧版本不能无条件改走 CPU 后声称复现历史 GPU 像素。应保留并验证相应后端语义，
或明确限制兼容范围；Auto 回退和 Force 报错约定不变。

VNG 的 OpenMP 优化只改变调度和暂存方式，不改变有效通道的整数运算。每批从固定
256 行及上下各两行的原始双线性快照读取，避免并行写回污染后续输入；单线程或未启用
OpenMP 时仍走原实现，非 Bayer VNG 也不启用此优化。性能优化必须通过未优化依赖生成的像素基准，不能用两个都链接
新依赖的程序互相比较后声称兼容。实现与诊断工具见
[LibRaw 补丁说明](../third_party/libraw/README.md#parallel-vng)。

## 客户端与配方

- Mac、Windows 在调整栏提供每张照片的处理版本选择。选择立即参与重渲染和本地保存，
  并保留所有滑块与外观参数；重置调整不改变处理版本。
- 中性原图、几何对比图、白平衡探测、自动曝光和批量任务均沿用所选身份。
  批量任务保持冻结快照，不把来源照片的处理版本替换成当前应用默认。
- CLI schema 5 要求根字段 `processing`，两端 Agent recipe 序列化使用 schema 5。
  schema 1–4 保留原有严格字段集合，隐式采用版本 1；不允许附加 `processing`。
  把版本 2 序列化为 schema 1–4 会报错，不允许丢弃身份后输出旧格式。
- 无法理解的编辑库阻止照片恢复；无法理解的批量日志阻止恢复和隐式替换。
  这些拒绝不改写原有文件。

## 接入验收

1. 从指定旧版本生成关闭、亮度、色度和组合降噪的基准，包含 Bayer、非 Bayer、
   负值、近黑和高光；新程序的旧版本路径与这些基准比较。
2. 旧记录缺字段、新记录显式版本、未知版本及旧批量任务均有真实读写回归。
   仅打开旧记录不能改写版本；普通参数修改和取消也不能触发升级。
3. 同一 session 执行旧 → 新 → 旧，分别与全新 session 比较；覆盖白平衡、
   交互预览、精确预览和文件导出。
4. 每个目标客户端分别验证处理身份及 C ABI 映射。不同端采用不同算法时，不要求输出
   相等；明确各端的支持范围和转换行为。硬件没有实际运行的 GPU 后端保持未验证，
   不以着色器源码相似或 CPU 测试通过代替，也不把未开展的移动端适配作为桌面验收失败。

画质、保存／重开、性能和 CPU/Metal 一致性分别验收。版本身份和兼容测试不替代
画质评价，也不把未运行的平台检查或远端 CI 表述为通过。
