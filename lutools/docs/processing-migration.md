# 旧处理版本自动迁移与回退

本契约适用于四端单张照片打开后的 `rawlab/1|2/standard` → `rawlab/3/standard` 迁移。
读取旧记录先恢复原处理身份并显示原画面，再后台尝试换算。它不扫描整个照片库，
也不改写原图、旧批量任务或 CLI recipe。手动处理版本选择仍是保留数值的直接切换。

## 资格与参数

自动迁移处理普通 SDR 编辑；HDR 编辑、AI 降噪和大师配方不参与。不可用的外观、
尚未保存的修改、交互操作及正在导出时不提交迁移。GPU Force 不参与自动匹配；
Auto 保持现有 CPU 回退约定。版本 1 的去马赛克和降噪变化也计入最终误差。

只换算曝光、对比度、高光、阴影、饱和度、黑场、白场、鲜艳度、清晰度、去朦胧十项。
白平衡、外观及其强度、HSL、曲线、降噪、锐化、效果、镜头与几何设置保持原记录值。
原生 C 结果使用核心单位，其中高光符号与桌面 UI 相反；各客户端负责转换单位。
Sony RAW 的旧处理版本沿用 `v0.10.0` 使用的 inset crop。新旧解码有效区的起点或尺寸
有变化时，自动迁移保留旧处理版本及其画幅。手动选择版本 3 会改用完整有效区。

核心在私有会话中复制完整渲染配置，不修改原会话、源文件或外观文件。最长边 384 的
工作图用于有界坐标搜索，最多评估 161 个候选；加上旧参考与两次完整验证，最多执行
164 次渲染。搜索未必找到数学最优解，找不到合格参数时允许保留旧版。

## 验收

最终验证重新渲染完整源图，包含原有外观、几何和其他调整，不拿交互预览替代。
对最终 SDR 显示值逐像素比较；这不是逐像素无损或感知等价的承诺。

- 参数搜索使用最长边 128 的网格均值和少量原尺寸采样，不能决定最终是否迁移。
- 完整验证保存全部像素的 16-bit RGB，每通道量化误差不超过 `1/65535`。
- 全图 RGB RMSE 不超过 `2/255`。
- 所有像素最大通道误差的 P99 不超过 `6/255`。
- 最差原尺寸 `64×64` 分区 RGB RMSE 不超过 `4/255`。
- 所有原尺寸水平、垂直相邻像素的梯度差 RMSE 不超过 `2/255`。

任一超限则拒绝；非有限值、渲染失败、取消或源文件/外观改变不产生可提交结果。
这些阈值是保守工程门限，不能证明人眼完全看不出差异。跨相机、降噪与复杂外观的
覆盖范围应由实测记录说明，不能从少数样片推断全部相机均已标定。完整验证仅保留旧帧的
16-bit RGB 快照，每像素 6 字节；新帧直接逐像素比较，不再分配第二份完整快照。
内存不足时保留旧记录，不降为缩图验收。

## 原子保存与状态

提交前重新验证照片、打开/编辑修订、外观与完整已保存记录。持有编辑库写锁时再次
比较完整旧记录，只有仍相同才通过一次原子写入保存新设置和原始快照。
新参数持久化成功后才发布到界面。并发保存优先，后台旧结果不能覆盖后续修改。
普通保存保留迁移记录；迁移或回退后只重建该照片的内存历史，不影响其他照片。

迁移记录使用独立 `policyVersion=1`、`targetVersion=3`，不复用编辑格式版本。
未写入这两个字段的早期 Windows 迁移记录按策略 1、目标 3 读取。

| 状态 | 当前画面 | 再次打开 |
|---|---|---|
| `migrated` | 合格的新版本参数 | 保留新版本与完整旧设置备份 |
| `kept` | 原版本和原参数 | 同一设置不重试；后续改过设置可重新尝试 |
| `rolledBack` | 迁移前完整设置 | 不再自动迁到版本 3 |

一次打开至多尝试一次。用户编辑、切图或取消使当前结果失效；本次打开不立即重新
启动拟合，后续打开可以重新考虑。取消及异常不保存 `kept`，也不把错误说成画质超限。

“回到迁移前”在照片处理设置中提供。确认文案明确：恢复全部迁移前调整，替换迁移后
的修改。回退先保存当前修改，再在锁内比较当前记录，原子恢复原快照并写入
`rolledBack`；备份跨应用重启有效。写入失败保留原磁盘内容与当前画面。

## 重置与回执

「重置全部调整」会清除该照片的处理迁移回执，`migrated`、`kept`、`rolledBack` 三种状态
一并清除；重置后不再提供「回到迁移前」。撤销历史不携带回执，因此重置后撤销只恢复调整
数值，无法恢复回滚能力。同理，被回退过的照片在重置后丢失该选择，下次打开可能重新尝试
迁移。四端行为一致。
