# EKTAR 100 Phuket v2 Strong

按用户反馈加强默认 100% 时的风格，不改变应用的全局胶片强度默认值，也不覆盖 v1。仍是扫描外观启发的人工调色模型，不是胶片的实测物理还原。

## 使用

生成文件：`output/ektar100-phuket-v2/EKTAR_100_Phuket_v2_Strong_FLog2_FGamut_65.cube`。

在 RawLab 中作为新 LUT 导入，先使用 100% 强度。输入仍为原始 F-Gamut / F-Log2、D65、full range；输出为 sRGB 编码的 BT.709/sRGB 原色。不要直接套在普通 sRGB JPEG 或已经完成胶片扫描显影的照片上。

## 变化

| 参数 | v1 | v2 Strong |
| --- | --- | --- |
| 色调曲线对比 | 1.62 | 1.82 |
| 基础彩度系数 | 1.055 | 1.105 |
| 绿色额外彩度 | 0.065 | 0.105 |
| 蓝色额外彩度 | 0.075 | 0.120 |
| 肤色区彩度抑制 | 0.075 | 0.125 |
| 绿色明度偏移 | -0.009 | -0.014 |
| 蓝色明度偏移 | -0.008 | -0.013 |

加强明暗分离、蓝绿的中间调彩度及色彩浓度；保留原来的蓝色色相方向，只略增加绿色偏移。肤色有独立的饱和度约束，中灰锚点、曝光和白平衡不变。参数不是应用滑杆的百分比，不能简单视为旧版的某个固定强度值。

v1 只增加了可选参数传入，其默认参数和默认结果不变；v2 复用同一模型与色彩转换，避免维护两份算法。

## 生成与检查

从仓库根目录运行，Python 环境需要 NumPy；对比脚本额外需要 Pillow：

```bash
lutools/.venv/bin/python experiments/ektar100-phuket-v2/generate.py
lutools/.venv/bin/python -m unittest discover -s experiments/ektar100-phuket-v2 -p 'test_*.py'
lutools/.venv/bin/python experiments/ektar100-phuket-v2/validate.py
```

`validate.py` 读取 v1 本地 `.cache/` 中冻结的 F-Log2/F-Gamut RAW 解码及参考 CUBE。缓存不随 Git 分发；无缓存时先按 v1 的流程生成参考数据。它只比较 LUT，不把已调色 JPEG 再套一次 LUT，也不把旧缓存说成当前 RAW 解码器的新验证结果。

本次检查（2026-10-07）：

- 8 项测试通过：原版回归、中灰锚点与对比、蓝绿增强、合成肤色约束、灰阶、65-grid 范围、插值误差、CUBE 写入及声明。
- v1 全部 274625 个采样点与已有参考文件一致，误差仅为原文件九位小数的序列化精度。
- 同曝光、同相机白平衡、同一份解码的 10 张照片均完成 v1/v2 的 100% 对比；v2 没有像素通道达到 0 或 1。
- 12000 个合成摄影颜色的解析模型与 65-grid 三线性插值对比：通道误差 p99 约 0.01064，最大约 0.02993。这是 LUT 采样误差，不是胶片匹配精度。
- 灰阶三线性插值只在低于 0.001 的近黑输出出现微小非单调，最大负步进约 0.0000055，小于一个 16-bit 码值；不宣称数学上严格单调。
- 现有 RawLab C++ 照片入口成功读取新版 CUBE 并将真实 Sony RAW 导出为全分辨率 JPEG，未改变默认曝光或白平衡。

LUT、对照图和逐图统计位于忽略的 `output/ektar100-phuket-v2/`。原始照片、旧版 CUBE、已导入的应用预设均未覆盖；没有修改正在进行的跨相机预设或应用代码。
